    Operators, overflow & decision making

    This module covers the operators you use every day (%, ==, ++/--) and how to avoid integer overflow when multiplying. It then covers the ways C makes decisions: if, else-if ladders, nested if, and switch. A few files contain small logic mistakes, and spotting them is good practice.

    💡 Key ideas

    Comparison gives 0 or 1

    In C, a == b evaluates to 1 (true) or 0 (false). <stdbool.h> adds the bool type and the words true and false.

    bool result = (5 == 7); // 0

    Modulus %

    a % b is the remainder after dividing a by b: 5 % 3 is 2. It is used for even/odd and divisibility tests.

    Overflow and 1LL *

    int * int is calculated in int even when you store the result in a long long, so 100000*100000 overflows. Make one side a long long first.

    long long r = 1LL * a * b;

    Pre vs post increment

    a++ gives the old value and then adds 1. ++a adds 1 first and gives the new value. The same rule holds for --.

    Else-if ladder order

    Conditions are checked from the top, so put the strictest one first (>= 80 before >= 70). A later branch with the same condition can never run.

    Dangling else

    An else always belongs to the nearest unmatched if in its block. Braces make the pairing obvious.

    switch / case / break

    switch jumps to the case that matches the value. break stops there; without it, execution falls through into the next case. default handles every other value.

    a * b is calculated in int first and overflows. Only the already-wrong result is then converted to long long.

    #include <stdio.h>

int main() {
    // Demonstrating post-increment (a++)
    int a = 15;
    printf("Post-increment: a++ \n");
    printf("Value of a during print: %d\n", a++);
    printf("Value of a after increment: %d\n\n", a);

    // Demonstrating pre-increment (++b)
    int b = 30;
    printf("Pre-increment: ++b \n");
    printf("Value of b after increment: %d\n", ++b);
    printf("Value of b in next statement: %d\n\n", b);

    // Demonstrating post-decrement (c--)
    int c = 40;
    printf("Post-decrement: c-- \n");
    printf("Value of c during print: %d\n", c--);
    printf("Value of c after decrement: %d\n\n", c);

    // Demonstrating pre-decrement (--d)
    int d = 40;
    printf("Pre-decrement: --d \n");
    printf("Value of d after decrement: %d\n", --d);
    printf("Value of d in next statement: %d\n", d);

    return 0;
}
    Input

    This program reads no input.

    Output 
    Post-increment: a++ 
Value of a during print: 15
Value of a after increment: 16

Pre-increment: ++b 
Value of b after increment: 31
Value of b in next statement: 31

Post-decrement: c-- 
Value of c during print: 40
Value of c after decrement: 39

Pre-decrement: --d 
Value of d after decrement: 39
Value of d in next statement: 39

    Reading the output. Compare each pair of lines: the post forms (15, then 16; 40, then 39) change the value after it is used. The pre forms (31, 31; 39, 39) change it before.

    How it works, step by step
    1. printf("%d", a++) prints 15 and only then makes a 16.
    2. printf("%d", ++b) makes b 31 first, so it prints 31.
    3. c-- prints 40, and c becomes 39 afterwards.
    4. --d makes d 39 first, so it prints 39.
    ✅ Check yourself: If x = 3, what are y and x after y = x++ * 2;?
    y = 6 (it uses the old value 3) and x = 4.

    #include <stdio.h>

int main() {
    int marks = 76;

    if(marks >= 80){
        printf("A+");
    } else if(marks >= 70) {
        printf("A");
    } else if(marks >= 70) {
        printf("A-");
    }
    return 0;
}
    Input

    This program reads no input.

    Output 
    A

    Reading the output. The program prints A.

    How it works, step by step
    1. The first test, marks >= 80, fails for 76.
    2. The next test, marks >= 70, passes, so the program prints A and skips the rest of the ladder.
    3. The last branch never runs (see Watch out).
    Watch out. The third branch repeats marks >= 70, so A- can never be printed. It was probably meant to be marks >= 60.
    ✅ Check yourself: Why must >= 80 be checked before >= 70?
    An 85 also passes >= 70. If that test came first, 85 would get A instead of A+.

    Input

    This program reads no input.

    Output 
    Odd Positive

    Reading the output. It prints Odd Positive , but 4 is even: the labels in the first block are swapped (see Watch out).

    How it works, step by step
    1. The first block tests x % 2 != 0.
    2. The second block tests x > 0.
    3. The two blocks are independent, so both always print something.

    Odd Negative (the first part because of the swap bug). 0 is really even and is neither positive nor negative.

    #include <stdio.h>

int main() {
    char grade;
    int day;

    printf("Enter your grade (A, B, C, D, F): ");
    scanf("%c", &grade);

    switch(grade) {
        case 'A':
            printf("Excellent!\n");
            break;
        case 'B':
            printf("Well done!\n");
            break;
        case 'C':
            printf("Good!\n");
            break;
        case 'D':
            printf("Sufficient!\n");
            break;
        case 'F':
            printf("Failed!\n");
            break;
        default:
            printf("Invalid grade!\n");
    }

    printf("Enter your day (1-7): ");
    scanf("%d", &day);

    switch(day) {
        case 1:
            printf("Monday\n");
            break;
        case 2:
            printf("Tuesday\n");
            break;
        case 3:
            printf("Wednesday\n");
            break;
        case 4:
            printf("Thursday\n");
            break;
        case 5:
            printf("Friday\n");
            break;
        case 6:
            printf("Saturday\n");
            break;
        case 7:
            printf("Sunday\n");
            break;
        default:
            printf("Invalid day!\n");
    }
}
    Input (stdin)
    B
5

    A grade letter on line 1, then a day number from 1 to 7.

    Output 
    Enter your grade (A, B, C, D, F): Well done!
Enter your day (1-7): Friday

    Reading the output. The prompts and answers appear on the same lines because the input is not echoed: Enter your grade ...: Well done!, then Enter your day (1-7): Friday.

    How it works, step by step
    1. Read grade with %c and switch on it: 'A' prints Excellent, 'B' prints Well done, and so on.
    2. Each case ends with break so only its own message prints.
    3. Read day with %d (which skips the leftover newline) and switch on 1 to 7.
    4. Any other value goes to default, which prints an Invalid message.
    ✅ Check yourself: What happens if you delete the break after case 'B'?
    Execution falls through, so grade B prints Well done! and then Good!.

    📌 Remember

    • Comparisons give 1 or 0, and bool makes that clearer.
    • Use 1LL * a * b so the multiplication happens in 64 bits.
    • x++ uses the old value; ++x uses the new one.
    • Order an else-if ladder from strictest to loosest, and never repeat a condition.
    • In a switch, end each case with break unless you want fall-through.

    ✅ Check yourself

    int a = 50000, b = 50000; long long r = a * b; Is r correct?
    No. 2.5×10^9 overflows int before it is stored. Use 1LL * a * b.
    What does x % 2 == 1 return for x = -3 in C?
    False, because -3 % 2 is -1. Test odd numbers with x % 2 != 0.
    When is a switch a better fit than an else-if ladder?
    When you compare one integer or char against a list of exact values.
    What is printed by int i = 5; printf("%d %d", i++, i);?
    The result is undefined: C does not say which argument is evaluated first. Never change and read the same variable in one call.
