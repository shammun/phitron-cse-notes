    Stack & queue problem practice

    A practice module with no new code: you use the stack and queue you already built to solve judge problems. The goal is to recognise when a problem is secretly a stack problem (matching, undo, most-recent-first) or a queue problem (first come, first served, rotating order).     🧭 Start here

    There is no new code today. Everything you need was built in Modules 13 and 14. What this day trains is one small decision you have to make before writing a single line: is this a stack problem or a queue problem?

    Two everyday pictures answer it. A canteen counter has a pile of washed plates. New plates go on the top, and whoever needs a plate takes the top one, the plate put down last. A ticket window has a line of people. You join at the back, and the person served next is the one who has been waiting longest.

    pile of plates        ticket line

  [ D ]  <- take       A  B  C  D
  [ C ]                ^        ^
  [ B ]                serve    join
  [ A ]                here     here

    So the question to ask a problem is: when the time comes to deal with something, is it the newest thing that must be dealt with, or the oldest? Newest first means a stack. Oldest first means a queue. Nothing else about the problem matters for this choice.

    First worked example. Check that the brackets in ( [ ] ) are balanced. You read ]. Which opening bracket is it supposed to close? Not the first one you saw, but the most recent one still waiting, which is [. The last thing seen has to be dealt with first, so the waiting brackets belong on a stack.

    string:  ( [ ] )

read (   push        stack: (
read [   push        stack: ( [
read ]   top is [ -> pop     stack: (
read )   top is ( -> pop     stack: empty

stack empty at the end  ->  balanced

    Notice what the stack saved you. Without it, for every closing bracket you would walk backwards through the string hunting for the nearest opening bracket that is still unmatched. That is a loop inside a loop: O(n²), which on a string of 100000 characters is about 10,000,000,000 steps and will not finish in a second. With a stack every character is pushed at most once and popped at most once, so the whole scan is O(n).

    Second worked example, this time with arrival order. A queue holds 1 2 3 4 5 and you must reverse only the first 3. Pour those 3 through a stack, because a stack hands them back in the opposite order, then rotate the untouched 2 items from the front to the back so they end up behind again.

    queue: 1 2 3 4 5      k = 3

pop 3 into a stack    stack: 3 2 1  (top first)
                      queue: 4 5
push them back        queue: 4 5 3 2 1
rotate 5 - 3 = 2      queue: 5 3 2 1 4
  front to back       queue: 3 2 1 4 5

    Three patterns cover most of the linked problems. Matching and cancelling: push each character, and pop instead of pushing when the new one cancels the top. Brackets work this way, and so do backspaces and removing adjacent duplicates. For abbaca the stack goes a, ab, then the second b cancels the b, the next a cancels the a, so c and a are pushed and ca is what is left.

    Next greater element: for every number, find the first larger number to its right. Comparing every pair is O(n²). Instead walk from right to left with a stack holding only the numbers that could still be somebody's answer: pop everything not larger than the current value, and what is left on top is the answer.

    Simulation with a queue: when the problem describes people or jobs arriving and being handled in order, act the story out. Join at the back with push, serve the front with front() and pop(), and send someone to the back of the line by popping and pushing the same value.

    if(!st.empty() && st.top() == c) st.pop();
else st.push(c);

    Two habits save most of the wrong answers here. Always check empty() before top(), front() or pop(), because reading the top of an empty stack is not an error message, it is undefined behaviour. And remember the stack only lets you touch the top: to reach the bottom, or to keep a running minimum, you need a second stack or a recursive call to hold the rest while you work.

    The concepts below name each pattern with its snippet, and the practice links are the problems to try. Decide plates or ticket line first, and the code usually follows in a few lines.

    💡 Key ideas

    Stack = last in, first out

    A stack only lets you touch the top. Use it when the newest item must be handled first, like the last opened bracket or the last typed character.

    stack<char> st; st.push('('); st.top(); st.pop();

    Bracket matching

    Push every opening bracket. On a closing bracket, the top must be its partner; if the stack is empty or the top does not match, the string is invalid. At the end the stack must be empty.

    Stack as an undo button

    For problems like 'backspace' or 'remove adjacent duplicates', push characters and pop when the new character cancels the top. What is left in the stack is the final string (read it bottom to top).

    if(!st.empty() && st.top()==c) st.pop(); else st.push(c);

    Reversing with a stack

    Pouring a queue into a stack and back reverses it, because the stack gives items back in the opposite order. To reverse only the first k items, pour k items through a stack, then rotate the remaining n-k items to the back.

    Inserting at the bottom of a stack

    You cannot reach the bottom directly. Pop everything into a helper (another stack or recursion), push the new value, then push everything back.

    Min stack

    Keep a second stack that stores the minimum so far at every level. Push min(x, minStack.top()) together with each push, and pop both together, so getMin is O(1).

    mn.push(mn.empty() ? x : min(x, mn.top()));

    Queue = first in, first out

    A queue adds at the back and removes at the front. Use it when order of arrival matters, or to rotate items (pop from front, push to back).

    queue<int> q; q.push(x); q.front(); q.pop();

    📌 Remember

    • Newest-first or 'cancel the last thing' problems are stack problems.
    • Arrival-order or rotation problems are queue problems.
    • Always check empty() before top(), front() or pop().
    • A stack reverses order; use that to reverse a queue or part of it.
    • A second stack of running minimums gives O(1) getMin.

    ✅ Check yourself

    For the string ([)], at which character does the bracket check fail, and why?
    At ): the top of the stack is [, which is not the partner of ).
    Why is a string like (( invalid even though no mismatch happens?
    Because the stack is not empty at the end; two brackets were never closed.
    You push 5, 3, 7 into a min stack. What does the helper stack hold, bottom to top?
    5, 3, 3 — each level stores the smallest value seen so far.
    How do you reverse only the first k items of a queue of size n?
    Pop k items into a stack, push them back into the queue (now reversed at the back), then move the front n-k items to the back once each.
