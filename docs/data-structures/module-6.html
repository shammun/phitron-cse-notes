    💡 Key ideas

    Reference to a pointer

    Passing Node* head gives the function a copy of the address, so changing head inside does nothing outside. Node* &head passes the pointer itself, so the caller sees the new head.

    void insert_at_head(Node* &head, int val)

    Insert at head, O(1)

    Point the new node at the current head, then make the new node the head. Order matters: link first, move head second.

    newNode->next = head;
head = newNode;

    Insert at tail, O(n) vs O(1)

    Without a tail pointer you walk to the last node every time (O(n)). Keeping a tail pointer lets you attach directly and move tail forward (O(1)).

    tail->next = newNode;
tail = newNode;

    Empty list case

    When head == NULL there is no node to attach to, so the new node becomes both head and tail.

    Insert at an index

    Walk to the node just before the position (idx - 1 steps), then point the new node at its successor and the previous node at the new node.

    newNode->next = tmp->next;
tmp->next = newNode;

    Reading until a sentinel

    Read values in a loop and stop when you see -1; each other value is added at the tail.

    Recursion for reverse printing

    Call the function on next first and print afterwards. The prints then happen while the calls return, from the last node back to the first.

    print_reverse(tmp->next);
cout << tmp->val;

    Visited array

    When values are small (at most 100), a bool visited[101] array detects repeats in one pass.

// change in pointer's address inside the function is not reflected in the main function
void fun(int* p){
    cout << "Value of p: " << *p << endl;
    // *p = 100;
    // cout << "Inside fun()" << *p << endl;
    int y = 100;
    p = &y;
    cout << "Address of p inside fun()" << &p << endl; // prints 0x61ff08
}

// use & before the pointer to pass the reference of the pointer
// using & before the pointer will change the pointer p in the main function
void fun2(int* &p){
    // *p = 100;
    // cout << "Inside fun()" << *p << endl;
    // int y = 100;
    // p = &y;
    p = NULL;
    cout << "Address of p inside fun()" << &p << endl; // prints 0x61ff08
}

int main(){
    int x = 10;
    int* p= &x;

    // if we change a pointer in a function, it will not change the pointer in the main function

    // fun uses a copy of the pointer p
    fun(p);
    // cout << "Inside main()" 
    // cout << x << endl; 

    cout << *p << endl; // prints 10 and not 100

    // because the pointer p in the main function and the pointer 
    // p in the fun function are different pointers

    fun(p);
    cout << "Address of p in main() " << &p << endl; // prints 0x61ff00
    

    // But, if we want the pointer p in the main function to point to the
    // variable y in the fun function, we need to pass the address of the pointer p
    // to the fun function.

    // This is called passing the reference of a pointer to a function
    // fun2 uses the reference of the pointer to p
    fun2(p);

    cout << "Address of p in main() " << &p << endl; // prints 0
    // prints the same address as the address of p in the fun2 function

    // the address of p in the main function is changed by calling the fun2 function

    // the value of y will be deleted after the fun2 function is executed and returned in main
    // function

    return 0;
}

    How it works, step by step
    1. In main, p points to x = 10.
    2. fun(p) prints *p (10), then makes its own copy point to a local y. main's p is untouched, so *p is still 10.
    3. fun prints &p, the address of its copy, which differs from main's &p.
    4. fun2(p) sets p = NULL. Because p is a reference, main's pointer really becomes NULL.
    5. fun2 prints the same address as main's &p, showing it is the same variable.
    Watch out. After fun2, p is NULL, so *p would crash. Also, pointing a pointer at a local variable (p = &y) that outlives the function would leave it dangling.
    ✅ Check yourself: Why does insert_at_head need Node* &head rather than Node* head?
    It changes which node head points to; without the reference, only the function's copy would change.

    /*

Take a singly linked list as input and check if the linked 
list is sorted in ascending order.

Input:
1 5 6 8 9 -1

Output:
YES

Input:
2 4 6 5 8 4 -1

Output:
NO

*/

#include <iostream>
#include <vector>
#include <algorithm>
#include <string>
using namespace std; // Allows us to avoid prefixing standard library objects with `std::`.

class Node{
    public:
        int val;
        Node* next;
    
    Node(int val){
        this->val = val;
        this->next = NULL;
    }
};

void insert_at_tail(Node* &head, Node* &tail,int val){
    Node* newNode = new Node(val);
    if(head==NULL){
        head = newNode;
        tail = newNode;
        return;
    }
    tail->next = newNode;
    tail = newNode;
}

void ascending_sort_check(Node* head){
    Node* tmp = head;
    while(tmp->next != NULL){
        if(tmp->next->val < tmp->val){
            cout << "NO";
            return;
        }
    }
    cout << "YES";
}

int main(){
    Node* head = NULL;
    Node* tail = NULL;

    int val;
    // while(true){
    while(cin >> val){
        // cin >> val;
        if(val == -1){
            break;
        }
        insert_at_tail(head, tail, val);
    }

    ascending_sort_check(head);

    return 0;
}
    Input (stdin)
    5 2 6 8 -1

    Values ending with -1. This input breaks the order at the very first pair, the only kind of input the buggy loop can finish on.

    Output 
    NO

    Reading the output. NO, because 2 is smaller than 5.

    How it works, step by step
    1. Read values with while (cin >> val) and stop on -1.
    2. ascending_sort_check looks at each node tmp and its tmp->next.
    3. If the next value is smaller, print NO and return.
    4. If the walk finishes, print YES.
    Watch out. The loop never moves tmp forward (tmp = tmp->next; is missing), so whenever the first pair is in order it loops forever. Add tmp = tmp->next; at the end of the loop body. An empty list would also crash on tmp->next.
    ✅ Check yourself: After fixing the bug, what does 1 5 6 8 9 -1 print?
    YES.

    📌 Remember

    • Pass head (and tail) as Node* & whenever the function may change them.
    • Head insert: newNode->next = head; head = newNode;, O(1).
    • Tail insert is O(1) with a tail pointer, O(n) without.
    • Middle insert: stop one node early, link the new node to the rest first, then link the previous node to it.
    • Always set next = NULL in the constructor; garbage pointers cause endless loops.
    • Recurse first, print later to print a list backwards.

    ✅ Check yourself

    What is wrong with void insert_at_head(Node* head, int val)?
    The function changes only its copy of head, so the caller's list never gets the new first node.
    Why is building a list of n values with the walking tail insert O(n^2)?
    Each insert walks the whole current list: 1 + 2 + ... + n steps in total.
    To insert at 0-based index 3, which node must tmp stop on?
    The node at index 2, the one just before the new position.
    How much extra memory does recursive reverse printing use?
    O(n), one stack frame per node.
