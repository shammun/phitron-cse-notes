    Time & space complexity

    Before learning data structures you need a way to say how fast a program is and how much memory it uses. This module teaches Big-O notation by counting how many times loops run: constant, logarithmic, square-root, linear, n log n and quadratic. Every later module uses this language to compare solutions.

    💡 Key ideas

    Big-O notation

    Big-O describes how the work grows when the input size n grows. We keep only the fastest-growing term and drop constant factors, so 2n + 5 becomes O(n).

    Counting loop runs

    A loop that moves its counter by a fixed step (i++, i += 2) up to something like n, n/2 or 2n runs a number of times proportional to n, so it is O(n).

    for(int i = 0; i < 2*n; i++)  // still O(n)

    Logarithmic loops

    When the counter is multiplied or divided each round (i *= 2, i /= 3), it reaches n in about log n steps. Doubling from 1 reaches 1,000,000 in only 20 steps.

    for(int i = 1; i <= n; i *= 2)  // O(log n)

    Square-root loops

    Divisors come in pairs i and n/i, and one of each pair is at most sqrt(n). So stopping at i*i <= n finds all divisors in O(sqrt n).

    for(int i = 1; i*i <= n; i++)

    Nested loops

    Loops inside loops multiply: n outer rounds times n inner rounds is O(n^2); an inner log loop gives O(n log n); an inner loop to m gives O(n*m).

    Adding sequential parts

    Loops placed one after another add up. O(n) + O(n) is still O(n); O(n^2) + O(n log n) is O(n^2) because the biggest term wins.

    Space complexity

    Space counts the extra memory the program asks for. A few variables are O(1), an array of size n is O(n), an n x n grid is O(n^2).

    int a[n];      // O(n) space

    Formula beats loop

    Sometimes maths removes a loop completely: the sum 1+2+...+n equals n*(n+1)/2, which is O(1).

    sum = n * (n + 1) / 2;

    /*
This program will ask users for a number and will sum all the numbers from 1 to that number.
*/

#include <iostream>
using namespace std;

int main() {
    int num, sum = 0;
    cout << "Enter a number: ";
    cin >> num;
    /*
    for(int i=1; i<=num; i++){
        sum += i;
    }
    */

    // Using the formula for sum of n numbers
    sum = (num * (num + 1)) / 2;
    
    cout << "Sum of numbers from 1 to " << num << " is " << sum << endl;

    return 0;
}

    10

    A single number n.

    Output 
    Enter a number: Sum of numbers from 1 to 10 is 55

    Reading the output. The prompt Enter a number: and the answer appear on the same line because the input you type is not echoed: for 10 you see Sum of numbers from 1 to 10 is 55 (10*11/2 = 55).

    How it works, step by step
    1. Print a prompt and read num.
    2. The commented loop would add 1, 2, ..., num one by one: num steps.
    3. Instead compute sum = (num * (num + 1)) / 2 in one step.
    4. Print the result in a sentence.
    Watch out. num * (num + 1) overflows int once num passes about 46,000. Use long long for big inputs.
    ✅ Check yourself: Why is the formula version O(1) while the loop version is O(n)?
    The formula does the same three arithmetic operations no matter how big num is; the loop runs once per number from 1 to num.

    #include <iostream>
using namespace std;

int main() {
    int n; // O(1)
    cin >> n; // O(1)

    // O(n)
    for(int i = 0; i < n; i++) {
        cout << i << " ";
    }

    // O(n)
    for(int i = 0; i < n-5; i++) {
        cout << i << " ";
    }

    // O(n)
    for(int i = 0; i < n/2; i++) {
        cout << i << " ";
    }

    // O(n)
    for(int i = 0; i < 2*n; i++) {
        cout << i << " ";
    }

    // O(n)
    for(int i = 0; i <= n; i+=2) {
        cout << i << " ";
    }

    return 0;
}

// Time complexity: O(n) -- consider the worst case scenario and ignore the constants 
// or consider the most dominant term

    Reading the output. All numbers come on one line. For n = 8, split them into the five loops: 0..7 (8 values), 0 1 2 (8-5 = 3), 0 1 2 3 (8/2 = 4), 0..15 (16 values), then 0 2 4 6 8.

    1. Read n.

    3. Loop 2 stops at n-5 and loop 3 at n/2: fewer rounds, but still a fixed fraction of n.

    5. Loop 5 goes to n in steps of 2: about n/2 rounds.
    6. Adding five O(n) parts gives O(5n), which we write as O(n).

    O(n): drop the constant factor 3 and the added 100.

    #include <iostream>
using namespace std;

int main() {
    int n; // O(1)
    cin >> n; // O(1)

    // O(log n)
    for(int i = 1; i <= n; i *= 2) {
        cout << i << " ";
    }

    // O(log n) -- log 3 base n
    for(int i=n; i>=1; i/=3){
        cout << i << " ";
    }

    // O(log n) -- log 2 base n
    for(int i=1; i<n; i++){
        cout  << i << " ";
        i *= 2;
    }

    // O(log n) -- log k base n
    int k = 3;
    for(int i=1; i<n; i++){
        cout  << i << " ";
        i *= k;
    }

    return 0;
}
    Input (stdin)
    20

    A single number n.

    Output 
    1 2 4 8 16 20 6 2 1 3 7 15 1 4 13

    Reading the output. For n = 20 the single line splits into four groups: 1 2 4 8 16 (doubling), 20 6 2 (dividing by 3), 1 3 7 15 (i -> 2i+1), 1 4 13 (i -> 3i+1). Each group is tiny compared to 20.

    How it works, step by step
    1. Loop 1 doubles i from 1 while i <= n: 1, 2, 4, 8, ...
    2. Loop 2 starts at n and divides by 3 while i >= 1: log base 3 of n rounds.
    3. Loop 3 prints i, then does i *= 2 inside the body and i++ in the header, so i becomes 2i+1 each round: still roughly doubling.
    4. Loop 4 does the same with k = 3, so i becomes 3i+1 each round: log base 3.
    5. The base of the log does not matter in Big-O, so all four are O(log n).
    Watch out. Loops 3 and 4 change i both in the body and in the header; trace them by hand once so the jump pattern does not surprise you.
    ✅ Check yourself: About how many times does for(i = 1; i <= n; i *= 2) run when n = 1,000,000?
    About 20 times, because 2^20 is roughly 1,000,000.

    #include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    // O(sqrt(n))
    for(int i=0; i<=sqrt(n); i++){
        cout << i << endl;
    }

    // find all the divisors of n
    // O(n))
    for(int i=1; i<=n; i++){
        if(n%i == 0){
            cout << i << " ";
        }
    }

    // O(sqrt(n))
    for(int i=1; i<=sqrt(n); i++){
        if(n%i == 0){
            cout << i << " " << n /i << " ";
        }
    }

    // O(sqrt(n))
    for(int i=1; i*i<=n; i++){
        if(n%i == 0){
            cout << i << " " << n /i << " ";
        }
    }

    return 0;
}

    How it works, step by step

    ✅ Check yourself: Why is it enough to test divisors only up to sqrt(n)?
    Divisors pair up as i and n/i, and the smaller one of every pair is at most sqrt(n), so each pair is found from its small side.

    #include <iostream>
using namespace std;

int main() {
    int n, m; // O(1)
    cin >> n >> m; // O(1)

    // O(n^2)
    for(int i = 0; i < n; i++) {
        for(int j = 0; j < n; j++) {
            cout << i << " " << j << endl;
        }
    }

    // O(n^2)
    for(int i = 0; i < n; i++) {
        for(int j = 0; j < n; j++) {
            cout << "Hello" << endl;
        }
    }

    // O(nxm)
    for(int i = 0; i < n; i++) {
        for(int j = 0; j < m; j++) {
            cout << "Hello" << endl;
        }
    }

    // O(n^3)
    for(int i = 0; i < n; i++) {
        for(int j = 0; j < n; j++) {
            for(int k = 0; k < n; k++) {
                cout << "Hello" << endl;
            }
        }
    }

    return 0;
}

    #include <iostream>
using namespace std;

int main() {
    int n; // O(1)
    cin >> n; // O(1)

    // O(n^2)
    for(int i = 0; i < n; i++) {
        for(int j = 0; j < n; j++) {
            cout << i << "Hello" << j << endl;
        }
    }

    // O(n*log n)
    for(int i = 0; i < n; i++) {
        for(int j = 1; j < n; j *= 2) {
            cout << i << "Hello" << j << endl;
        }
    }

    return 0;
}

    How it works, step by step

    4. Sorting algorithms like merge sort have this O(n log n) shape.

    #include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n >> m;
    int sum = 0; // memory space complexity O(1)
    int x; // memory space complexity O(1)
    double d = 3.14; // memory space complexity O(1)
    // time complexity depends on the number of loops while
    // space complexity depends on the number of variables or the array size

    // time complexity O(n)
    // space complexity O(1)
    for(int i = 0; i < n; i++) {
        sum += i;
    }

    // space complexity O(n)
    int a[n]; 
    // time complexity O(n)
    for(int i = 0; i < n; i++) {
        cin >> a[i];
    }

    // space complexity O(n^2)
    int a[n][n]; 
    
    // time complexity O(n)
    for(int i = 0; i < n; i++) {
        cin >> a[i][i];
    }

    // space complexity O(n*m)
    int a[n][m];
    // time complexity O(n)
    for(int i = 0; i < n; i++) {
        cin >> a[i][i];
    }

    return 0;
}

    📌 Remember

    • Count how many times the loop body runs; drop constants and smaller terms.
    • Counter +1 or +k: O(n). Counter *2 or /2: O(log n). Stop at i*i <= n: O(sqrt n).
    • Nested loops multiply, loops in sequence add.
    • Order from best to worst: O(1) < O(log n) < O(sqrt n) < O(n) < O(n log n) < O(n^2) < O(2^n).
    • Space complexity counts allocated memory: variables O(1), array O(n), grid O(n^2).
    • A maths formula can replace a whole loop (sum 1..n = n(n+1)/2).

    ✅ Check yourself

    What is the complexity of for(i=n; i>0; i/=2) for(j=0; j<n; j++)?
    O(n log n): the outer loop runs about log n times and the inner loop runs n times each.
    Is O(2n + n^2) the same as O(n^2)?
    Yes. The n^2 term dominates, and the 2n term is dropped.
    Roughly how many simple operations per second should you assume, and what does that mean for n = 10^5?
    About 10^8 per second, so O(n^2) = 10^10 is too slow while O(n log n) (about 1.7 * 10^6) is fine.
