    Binary trees & depth-first traversals

    This module starts trees. You build a small binary tree by hand with Node objects that have left and right pointers, then visit every node with the three depth-first orders: pre-order, in-order and post-order. The three orders are the same recursion with the print moved to a different place.

    4 programsFolder on GitHub ↗

    🧭 Start here

    Trees start here, and you already have almost everything you need. A linked list node held a value and one pointer, next, so the nodes formed a single line and a walk had only one way to go. Now change one thing: give the node two pointers instead of one, and call them left and right.

    That is the whole definition of a binary tree node. A missing child is NULL, exactly as the end of a list was NULL.

    class Node {
public:
    int val;
    Node* left;    // where a list had one next,
    Node* right;   // a tree node has two
    Node(int val){
        this->val = val;
        this->left = NULL;
        this->right = NULL;
    }
};

    Draw it and the consequence shows up at once. With one pointer the nodes lie in a line. With two, every node can send you two ways, so the picture spreads out downwards. Here is the small tree the programs on this page build by hand, with six nodes.

    a linked list:   10 -> 20 -> 40 -> NULL

the same 6 values as a tree:

              10
             /  \
           20    30
          /     /  \
        40    50    60

    Five words, all readable straight off that picture. The root is 10: the node at the top, the one nothing points to, and the one pointer you hold on to, just as head was your only handle on a list. A child hangs directly under another node, so 20 and 30 are the children of 10, and 10 is their parent. A leaf has no children at all, both pointers NULL: here 40, 50 and 60. A subtree is any node together with everything under it, so 30, 50, 60 form the right subtree of the root, and a subtree is itself a perfectly good tree.

    Height is how deep the picture goes. The longest path down is 10, 20, 40: three nodes on three levels, so height 3. Some books count the two steps between them instead and say 2, so check which a problem means.

    The new thing compared with lists is not the node, it is the walking. A list had one route, so a while loop did the job. Here the route splits in two at every node, and a loop cannot be in two places at once. Recursion can: a tree is a root plus a left subtree plus a right subtree, and each subtree gets the same function called on it. The base case is the empty tree.

    if(root == NULL) return;   // nothing here, go back

    So a full traversal is three lines: handle this node, go left, go right. And here is the point of the module. Those three lines can be written in different orders, and only the position of the visit changes. Move the cout and you get a different traversal with the same two recursive calls.

    void preorder(Node* root){        // Root, Left, Right
    if(root == NULL) return;
    cout << root->val << " ";   // visit before both
    preorder(root->left);
    preorder(root->right);
}
// cout between the two calls -> in-order
// cout after both calls       -> post-order

    Traced on the same little tree, the three orders come out like this. Follow one of them with a finger on the drawing above and you will see the walk is identical every time; only the moment a value is printed moves.

    pre-order   Root, Left, Right
   10  20  40  30  50  60     root first

in-order    Left, Root, Right
   40  20  10  50  30  60     root in the middle

post-order  Left, Right, Root
   40  20  50  60  30  10     root last

    Each order suits a different job. Pre-order sees a parent before its children, which is what you want when copying a tree. Post-order finishes both children before the parent, which is what deleting a tree needs: free the children first, because once the parent is gone you have lost the pointers to them. In-order becomes the interesting one in a later module, where a tree is arranged so that in-order hands the values back already sorted.

    All three visit every node once, so each is O(n), and the memory is the depth of the recursion, O(h) for height h. One caution while you experiment: root->left->right->val crashes on this tree, because 20 has no right child. Know a child exists before you follow it.

    The four programs below take one step each: build the tree by hand, then add pre-order, then in-order, then post-order, each keeping the earlier functions so you see all three outputs together.

    💡 Key ideas

    Binary tree node

    Each node stores a value and two pointers, left and right. A missing child is NULL. The top node is the root; a node with no children is a leaf.

    class Node { public: int val; Node* left; Node* right; };

    Linking nodes by hand

    Create nodes with new Node(x) and connect them by assigning root->left = a; and so on. You reach deeper nodes by chaining arrows, like root->right->left.

    Recursion on a tree

    A tree is a root plus a left subtree plus a right subtree. So a function can handle the root and call itself on the two subtrees. The base case is root == NULL: nothing to do.

    if(root == NULL) return;

    Pre-order (Root, Left, Right)

    Print the node first, then visit left, then right. The root always comes first in the output.

    cout << root->val; preorder(root->left); preorder(root->right);

    In-order (Left, Root, Right)

    Visit the whole left subtree, then print the node, then the right subtree. The root ends up in the middle.

    Post-order (Left, Right, Root)

    Visit both subtrees first and print the node last. The root always comes last, which is handy when children must be handled before parents (for example, deleting a tree).

    🔍 Worked examples

    Watch it happen: pre-order on this very tree

    Pre-order is three lines of code: print this node, walk the whole left subtree, walk the whole right subtree. The node in [ ] is the one the function is sitting on right now, and the line underneath grows every time something is printed.

    Follow it with a finger on the drawing. The walk goes down and back up exactly the same way for all three depth-first orders; only the moment the value is printed moves.

                   10
             /    \
           20      30
          /      /   \
        40      50    60

printed so far:  (nothing yet)

    preorder(root) is called on 10. Nothing has been printed yet, and the whole tree is still to do.

                  [10]
             /    \
           20      30
          /      /   \
        40      50    60

printed so far:  10

    The first line of the function is the cout, so 10 is printed straight away, before either child is looked at. Root first - that is what 'pre' means.

                   10
             /    \
          [20]     30
          /      /   \
        40      50    60

printed so far:  10 20

    Then preorder(root->left) goes to 20 and does the same thing: print, then go left, then go right.

                   10
             /    \
           20      30
          /      /   \
       [40]     50    60

printed so far:  10 20 40

    Down to 40 and print it. 40 is a leaf, so both of its calls hit if(root == NULL) return; and come straight back.

                  [10]
             /    \
           20      30
          /      /   \
        40      50    60

printed so far:  10 20 40

    Back up to 20, whose right child is NULL, then back up to 10. Nothing is printed on the way back up - a value is only printed when a call starts.

                   10
             /    \
           20     [30]
          /      /   \
        40      50    60

printed so far:  10 20 40 30

    Now the second call, preorder(root->right), finally runs. 30 is printed - and notice it waited until everything on the left was completely finished.

                   10
             /    \
           20      30
          /      /   \
        40     [50]   60

printed so far:  10 20 40 30 50

    Into 30's left subtree: print 50, and it is a leaf, so come back.

                   10
             /    \
           20      30
          /      /   \
        40      50   [60]

printed so far:  10 20 40 30 50 60

    Then 30's right child, 60. Every node has now been visited exactly once, so the whole walk is O(n).

                   10
             /    \
           20      30
          /      /   \
        40      50    60

printed so far:  10 20 40 30 50 60
in-order:        40 20 10 50 30 60
post-order:      40 20 50 60 30 10

    Done: 10 20 40 30 50 60, the same line the program prints. The other two orders take this identical walk and only move the cout. Put it between the two calls and you get in-order; put it after both and you get post-order, where a parent is never printed until both of its children are finished.

    /*

Implements a binary tree

*/


#include <iostream>
#include <vector>
#include <algorithm>    
#include <string>
#include <stack>

using namespace std;

class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* left;  // Pointer to the left node in the binary tree.
        Node* right; // Pointer to the right node in the binary tree.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
    Node(int val) {
        this->val = val;  // Assign the provided value to the 'val' member.
        this->left = NULL; // Initialize 'left' to NULL, meaning no left node by default.
        this->right = NULL; // Initialize 'right' to NULL, meaning no right node by default.
    }
};

int main(){
    Node* root = new Node(10);
    Node* a = new Node(20);
    Node* b = new Node(30);
    Node* c = new Node(40);
    Node* d = new Node(50);
    Node* e = new Node(60);

    root->left = a;
    root->right = b;
    a->left = c;
    b->left = d;
    b->right = e;

    cout << "The value of root is: " << root->val << endl;
    cout << "The value of a is: " << root->left->val << endl;
    cout << "The value of b is: " << root->right->val << endl;
    cout << "The value of c is: " << root->left->left->val << endl;
    cout << "The value of d is: " << root->right->left->val << endl;
    cout << "The value of e is: " << root->right->right->val << endl;

    return 0;
}

    This program reads no input.

    Output 
    The value of root is: 10
The value of a is: 20
The value of b is: 30
The value of c is: 40
The value of d is: 50
The value of e is: 60

    Reading the output. Six lines, 10 to 60, confirming each pointer path reaches the node you expected.

    How it works, step by step
    1. Node(int val) sets the value and makes left and right NULL.
    2. main creates root (10) and nodes a..e (20..60).
    3. Links: root->left = a, root->right = b, a->left = c, b->left = d, b->right = e.
    4. Each cout reaches a node from the root, e.g. root->right->left->val is 50.
    Watch out. Reading root->left->right->val here would crash: a->right is NULL. Always know a child exists before following it.
    ✅ Check yourself: Which nodes are leaves in this tree?
    40, 50 and 60. They have no children.

Pre-order traversal

Root  -> Left -> Right

*/

#include <iostream>
#include <vector>
#include <algorithm>    
#include <string>
#include <stack>

using namespace std;

class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* left;  // Pointer to the left node in the binary tree.
        Node* right; // Pointer to the right node in the binary tree.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
    Node(int val) {
        this->val = val;  // Assign the provided value to the 'val' member.
        this->left = NULL; // Initialize 'left' to NULL, meaning no left node by default.
        this->right = NULL; // Initialize 'right' to NULL, meaning no right node by default.
    }
};

void preorder(Node* root){
    if(root == NULL){
        return;
    }
    cout << root->val << " ";
    preorder(root->left);
    preorder(root->right);
}

int main(){
    Node* root = new Node(10);
    Node* a = new Node(20);
    Node* b = new Node(30);
    Node* c = new Node(40);
    Node* d = new Node(50);
    Node* e = new Node(60);

    root->left = a;
    root->right = b;
    a->left = c;
    b->left = d;
    b->right = e;

    cout << "The value of root is: " << root->val << endl;
    cout << "The value of a is: " << root->left->val << endl;
    cout << "The value of b is: " << root->right->val << endl;
    cout << "The value of c is: " << root->left->left->val << endl;
    cout << "The value of d is: " << root->right->left->val << endl;
    cout << "The value of e is: " << root->right->right->val << endl;

    cout << "Pre-order traversal: ";
    preorder(root);


    return 0;
}

    This program reads no input.

    Output 
    The value of root is: 10
The value of a is: 20
The value of b is: 30
The value of c is: 40
The value of d is: 50
The value of e is: 60

    Reading the output. After the six value lines: Pre-order traversal: 10 20 40 30 50 60. The root 10 is first.

    How it works, step by step
    1. preorder(root) returns at once if root is NULL.
    2. Otherwise it prints root->val first.
    3. Then it calls preorder(root->left) and finishes that whole side.

#include <algorithm>    
#include <string>

using namespace std;

    public:
        int val;     // Value stored in the node (data).

In-order traversal

Left -> Right -> Root

*/

#include <iostream>
#include <vector>
#include <algorithm>    
#include <string>
#include <stack>

using namespace std;

class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* left;  // Pointer to the left node in the binary tree.
        Node* right; // Pointer to the right node in the binary tree.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
    Node(int val) {
        this->val = val;  // Assign the provided value to the 'val' member.
        this->left = NULL; // Initialize 'left' to NULL, meaning no left node by default.
        this->right = NULL; // Initialize 'right' to NULL, meaning no right node by default.
    }
};

void preorder(Node* root){
    if(root == NULL){
        return;
    }
    cout << root->val << " ";
    preorder(root->left);
    preorder(root->right);
}

void inorder(Node* root){
    if(root == NULL){
        return;
    }
    inorder(root->left);
    cout << root->val << " ";
    inorder(root->right);
}

void postorder(Node* root){
    // if(!root){}
    if(root == NULL){
        return;
    }
    postorder(root->left);
    postorder(root->right);
    cout << root->val << " ";
}

int main(){
    Node* root = new Node(10);
    Node* a = new Node(20);
    Node* b = new Node(30);
    Node* c = new Node(40);
    Node* d = new Node(50);
    Node* e = new Node(60);

    root->left = a;
    root->right = b;
    a->left = c;
    b->left = d;
    b->right = e;

    cout << "The value of root is: " << root->val << endl;
    cout << "The value of a is: " << root->left->val << endl;
    cout << "The value of b is: " << root->right->val << endl;
    cout << "The value of c is: " << root->left->left->val << endl;
    cout << "The value of d is: " << root->right->left->val << endl;
    cout << "The value of e is: " << root->right->right->val << endl;

    cout << "Pre-order traversal: ";
    preorder(root);

    cout << "In-order traversal: ";
    inorder(root);
    
    cout << "Post-order traversal: ";
    postorder(root);

    return 0;
}

    2. It calls postorder(root->left), then postorder(root->right).

    📌 Remember

    • A binary tree node has a value plus left and right pointers; NULL means no child.
    • Tree recursion: handle NULL, then the node, then the two subtrees.
    • Pre-order = Root L R, In-order = L Root R, Post-order = L R Root.
    • Only the position of the print line changes between the three traversals.
    • Each traversal visits every node once: O(n) time.

    ✅ Check yourself

    A tree has root 1, left child 2, right child 3, and 2 has a left child 4. Give all three traversals.
    Pre: 1 2 4 3. In: 4 2 1 3. Post: 4 2 3 1.
    What stops the traversal recursion?
    Reaching a NULL child: the function returns without doing anything.
    Why is the extra memory O(h) and not O(1)?
    Each recursive call waits on the call stack, and at most one chain from the root to a leaf (height h) is waiting at a time.
