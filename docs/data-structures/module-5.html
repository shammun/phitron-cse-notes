    Singly linked list: nodes & traversal

    A linked list stores each value in its own node, and each node points to the next one. This module builds nodes by hand (on the stack and with new), adds a constructor, links them with next pointers, and walks the list with a temporary pointer. It explains why linked lists exist when arrays are fixed-size and costly to insert into.

    🧭 Start here

    This is the first data structure you build yourself, and it is the hardest jump in the course. Take it slowly; the idea is simple once the picture is right.

    Start from what is wrong with an array. An array is a row of seats, numbered and next to each other, and the number of seats is fixed the moment it is born. Suppose you hold 10 20 30 40 50 and you want 25 to sit third. There is no free seat there, so everything from 30 onwards must shuffle one place to the right before 25 can sit down:

    before   10  20  30  40  50
shift    10  20  __  30  40  50
insert   10  20  25  30  40  50

    With five values that is three moves and nobody minds. With 100000 values, inserting at the front moves 100000 of them, and doing that 100000 times is about 10^10 moves — far too slow. On top of that, the row cannot grow: if you declared 5 seats and a sixth value arrives, you have to build a bigger row and copy everything across.

    So picture the values differently. Instead of one long row of seats, give every value its own little box, and in each box write two things: the value, and the address of the next box. Like railway carriages: each carriage carries goods and is coupled to the one behind it. The boxes may sit anywhere in memory — they do not have to be neighbours — because each one says where the next is. One extra variable, head, holds the address of the first box, and the last box holds NULL to say the chain ends here:

    head
 |
 v
[10| ] -> [20| ] -> [30| ] -> [40| ] -> NULL

    Say plainly what is new. Until now, one name gave you the whole collection, and a[3] put you at the fourth value in a single step. Here you hold exactly one address — head — and there is no a[3]. The only way to the third box is to ask the first box where the second is, then ask the second where the third is.

    In code a box is a small class with the two fields, and a constructor that sets next to NULL so a new box starts unattached. new puts the box on the heap, so it stays alive, and -> reads a field through a pointer:

    class Node {
public:
    int val;
    Node* next;
    Node(int val){
        this->val = val;
        this->next = NULL;
    }
};

Node* head = new Node(10);
Node* a = new Node(20);
head->next = a;              // 10 is now coupled to 20
cout << head->next->val;     // prints 20

    Now walking the chain, and the one mistake everybody makes. To print every value you must move forward box by box. It is tempting to write head = head->next, but that destroys the list: the arrows only point forward, so the moment head moves off the first box there is no way back to it, and the whole start of the list is lost for good.

    So copy the address into a second pointer, tmp, and move that instead. head stays where it is, pointing at the front:

    Node* tmp = head;
while(tmp != NULL){
    cout << tmp->val << endl;
    tmp = tmp->next;
}
    tmp = head        tmp at [10]   print 10
tmp = tmp->next   tmp at [20]   print 20
tmp = tmp->next   tmp at [30]   print 30
tmp = tmp->next   tmp at [40]   print 40
tmp = tmp->next   tmp is NULL   stop

    Notice where the loop stops. The condition is tmp != NULL, not tmp->next != NULL. The second one looks reasonable and prints everything except the last value, because it stops while still standing on the last box. One of the programs below shows both so you can see the missing line.

    What have you bought with all this? Putting a value at the front is now two small changes, whatever the length of the list, and the list grows one box at a time, so no size has to be guessed in advance. What you have sold is the jump: reaching the 500th value costs 500 hops, and you cannot go backwards at all, because no box knows who points at it.

    The four programs below build the same short chain in three ways — plain objects, objects with a constructor, and boxes made with new — and then walk it with tmp.

    💡 Key ideas

    Node

    A small class holding a value val and a pointer next to the following node. The last node's next is NULL, which marks the end.

    class Node {
public:
    int val;
    Node* next;
};

    Why linked lists

    Arrays have a fixed size and need shifting to insert in the middle. A linked list grows one node at a time and inserts by changing a couple of pointers. The cost: extra memory for each pointer and no O(1) access by index.

    Constructor

    A constructor sets val and makes next = NULL as soon as the node is created, so you never forget to end the chain.

    Node(int val) { this->val = val; this->next = NULL; }

    Arrow operator

    p->val is short for (*p).val: follow the pointer, then take the member. Chaining head->next->next->val walks two links.

    Static vs dynamic nodes

    Node a(10); lives on the stack and dies when the function ends. new Node(10) lives on the heap until deleted, so it can outlive the function that made it. Real lists use dynamic nodes.

    Node* head = new Node(10);

    Head pointer

    The list is known only through head, the address of the first node. Lose it and you lose the whole list.

    Traversal

    Copy head into tmp and move tmp = tmp->next until tmp is NULL. Stopping at tmp->next == NULL instead would skip the last node.

    for(Node* tmp = head; tmp != NULL; tmp = tmp->next)

    Watch it happen: walking the list with tmp

    This is the walk that printing_singly_linked_list.cpp does. Watch two things: tmp moving one box at a time, and head never moving at all.

            tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed:

    Node* tmp = head; copies the address of the first box into a second pointer. Two names now stand on the same box, and nothing has been printed yet.

                    tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed: 10

    The loop prints tmp->val, then tmp = tmp->next reads the address written inside the 10 box and steps on to 20. head has not moved.

                            tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed: 10 20

    Same two lines again. There is no a[2] here: the only way to the third box was to ask the second one.

                                    tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed: 10 20 30

    Another hop, and 30 is printed. Four boxes means four hops, which is the price of a list.

                                            tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed: 10 20 30 40

    40 is printed, then tmp = tmp->next reads the NULL sitting in the last box. tmp now points at nothing, tmp != NULL is false, and the loop stops.

                                    tmp
head -> [10] -> [20] -> [30] -> [40] -> NULL
printed: 10 20 30
stopped early: tmp->next is NULL while on 40

    The other loop on the page is while(tmp->next != NULL). Standing on 40 it sees NULL ahead and stops before printing, so the last value never appears. That is the missing line in the program's output.

    head -> [10] -> [20] -> [30] -> [40] -> NULL
head still points at 10, so nothing was lost

    And this is the point of tmp: when the walk is over, head is still on the first box, so the list can be walked again, printed again, or changed. Nothing was spent.

    Watch it happen: why moving head loses the list

    The tempting shortcut is to walk with head itself and save a variable. Here is what it costs.

    Press ▶ to see the list disappear

    head
 |
 v
[10] -> [20] -> [30] -> [40] -> NULL

    The same four boxes, with head holding the address of the first one. Now suppose the loop body is head = head->next;.

            head
         |
         v
[10] -> [20] -> [30] -> [40] -> NULL
 ^ no name holds this box now

    head has stepped on to 20. The 10 box is still there and still points forward, but no name in the program holds its address any more, and the arrows only go one way. There is no way back.

                    head
                 |
                 v
[10] -> [20] -> [30] -> [40] -> NULL
^^^^^^^^^^^^  both of these are lost

    Another step. Two boxes are now out of reach for good, and the program cannot even tell: everything it can see still looks like a perfectly good list.

                            head
                         |
                         v
[10] -> [20] -> [30] -> [40] -> NULL
^^^^^^^^^^^^^^^^^^^^  three are lost

    One more. What started as a list of four is, as far as the program is concerned, a list of one.

                                    head
                                 |
                                 v
[10] -> [20] -> [30] -> [40] -> NULL
^^^^^^^^^^^^^^^^^^^^^^^^^^^^  all gone

    The last step puts NULL in head. The boxes are still sitting in memory, but nothing reaches them, so they can never be printed and never be freed. The whole list has leaked.

    head            tmp
 |               |
 v               v
[10] -> [20] -> [30] -> [40] -> NULL

    So you copy the address into a second pointer and move that one. tmp does the walking, head keeps the front. One extra variable buys back the whole list.

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>
using namespace std;

// Node class represents a single element in a linked list.
class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* next;  // Pointer to the next node in the linked list.
};

int main() {
    // Step 1: Declare three instances of the Node class to create the linked list.
    // Static nodes
    Node a, b, c;

    // Step 2: Assign values to each node.
    a.val = 10; // Assign 10 as the value of the first node.
    b.val = 20; // Assign 20 as the value of the second node.
    c.val = 30; // Assign 30 as the value of the third node.

    // Step 3: Link the nodes to form the linked list.
    a.next = &b;  // The 'next' pointer of the first node points to the address of the second node.
    b.next = &c;  // The 'next' pointer of the second node points to the address of the third node.
    c.next = NULL; // The 'next' pointer of the third node is NULL, indicating the end of the list.


    cout << "The value of a is: " << a.val << endl; 
    cout <<  "The value of b is: " << a.next->val << endl; 
    // (*a.next).val is the same as a.next->val
    cout << "The value of c is: " << a.next->next->val << endl;
    // (*(*a.next).next).val is the same as a.next->next->val

    // Why is this formatting used?
    // - `Node a, b, c;`: Nodes are declared together because they are part of the same linked list.
    //   This format shows that the nodes are related and belong to the same sequence.
    // - Separate assignments (`a.val = 10;`, etc.) improve clarity by explicitly showing
    //   which value is assigned to which node.
    // - Linking nodes (`a.next = &b;`, etc.) is done on separate lines to make it clear
    //   how the chain (linked list) is formed.
    // - `cout` statements are separated and include explanatory text. This helps beginners
    //   understand not only the value being accessed but also how to traverse the list.

    // Explanation of pointer traversal:
    // - `a.next->val`: Access the 'next' pointer of node `a` to reach node `b`, and then get its value.
    // - `a.next->next->val`: Chain two 'next' pointers starting from `a` to reach node `c` and get its value.
    // - This chaining illustrates how linked list traversal works in C++.

    return 0;
}
    Input

    This program reads no input.

    Output 
    The value of a is: 10
The value of b is: 20
The value of c is: 30

    Reading the output. Three lines showing 10, 20, 30. The second and third values were reached through the pointers, not by naming b and c.

    How it works, step by step
    1. Declare Node a, b, c; and set val to 10, 20, 30.
    2. Link them: a.next = &b, b.next = &c, c.next = NULL.
    3. a.val reads the first value directly.
    4. a.next->val follows one link to reach b.
    5. a.next->next->val follows two links to reach c.
    Watch out. Without a constructor, val and next start with garbage. Forgetting c.next = NULL would leave the list without a proper end.
    ✅ Check yourself: Write a.next->next->val without arrows.
    (*(*a.next).next).val

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>
using namespace std; // Allows us to avoid prefixing standard library objects with `std::`.

// Node class represents a single element in a linked list.
class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* next;  // Pointer to the next node in the linked list.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
        Node(int val) {
            this->val = val;  // Assign the provided value to the 'val' member.
            this->next = NULL; // Initialize 'next' to NULL, meaning no next node by default.
        }
};

// Main function: Entry point of the program.
int main() {
    // Step 1: Create three nodes using the constructor.
    // Here, the constructor is called with the values 10, 20, and 30 respectively.
    Node a(10), b(20), c(30);

    // Step 2: Link the nodes to form a chain (linked list).
    a.next = &b;  // The 'next' pointer of the first node points to the address of the second node.
    b.next = &c;  // The 'next' pointer of the second node points to the address of the third node.

    // Step 3: Output the values of the nodes to verify the linked list structure.
    cout << "The value of a is: " << a.val << endl; // Output the value of the first node.
    // Access the value of the second node using the 'next' pointer of the first node.
    cout << "The value of b is: " << a.next->val << endl; 
    // Explanation: 'a.next' is a pointer to the second node, and 'a.next->val' accesses its value.

    // Step 4: Demonstrate alternative syntax for accessing the value of the third node.
    // 'a.next->next' points to the third node, and 'a.next->next->val' accesses its value.
    cout << "The value of c is: " << a.next->next->val << endl; 
    // Equivalent expression using dereferencing: (*(*a.next).next).val
    // Explanation: 'a.next' gives the address of the second node, 
    // '*a.next' dereferences it to access the second node itself,
    // and '.next' accesses the pointer to the third node. Finally, '*(*a.next).next' dereferences it.

    // Why this formatting is used:
    // - Constructor usage (`Node(int val)`): Simplifies initialization by combining declaration and assignment.
    //   This is more efficient and cleaner than separately setting `val` and `next`.
    // - Linking nodes (`a.next = &b;`): This explicit assignment makes it clear how nodes are connected.
    // - Pointer traversal: Step-by-step traversal (`a.next->val`, `a.next->next->val`) demonstrates
    //   how linked list elements are accessed using pointers.
    // - Alternative syntax: Showing `(*(*a.next).next).val` helps beginners understand the equivalence
    //   between arrow operator (`->`) and dereferencing with dot operator (`.`).

    return 0; // End of the program.
}

    How it works, step by step
    1. The constructor Node(int val) uses this->val = val because the parameter has the same name as the member.
    2. It also sets this->next = NULL.
    3. Node a(10), b(20), c(30); creates three ready nodes.
    4. Link a.next = &b and b.next = &c; c.next is already NULL.
    5. Print values through the links.
    ✅ Check yourself: Why is this-> needed in this->val = val?
    The parameter val hides the member val; this->val names the member explicitly.

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>
using namespace std; // Allows us to avoid prefixing standard library objects with `std::`.

// Node class represents a single element in a linked list.
class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* next;  // Pointer to the next node in the linked list.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
        Node(int val) {
            this->val = val;  // Assign the provided value to the 'val' member.
            this->next = NULL; // Initialize 'next' to NULL, meaning no next node by default.
        }
};

// Main function: Entry point of the program.
int main() {
    // previously, Node a(10), b(20), c(30);

    // Dynamic node
    // For dynamic node, the node is created in the heap memory
    // and the pointer to the node is stored in the stack memory
    // So even after the function ends, the node will still be there in the heap memory
    
    Node* head = new Node(10); // Create the first node and store its address in 'head'.
    Node* a = new Node(20);   // Create the second node and store its address in 'a'.
    Node* b = new Node(30);  // Create the third node and store its address in 'b'.

    // previously a.next = &b; 
    // previously a was an object, so in the left side, we used . to access the member of the object

    (*head).next = a; // Link the first node to the second node using pointers.
    // because a is a pointer, so in the right side, we don't need to use &
    // but in the left side, we need to use * to dereference the pointer

    a->next = b; // previously, it was a.next = &b;

    cout << "The value of head is: " << head->val << endl; // Output the value of the first node.
    cout << "The value of a is: " << head->next->val << endl; // Output the value of the second node.
    cout << "The value of b is: " << head->next->next->val << endl; // Output the value of the third node.

    return 0;
}

    Reading the output. Values 10, 20 and 30, all reached from head.

    How it works, step by step
    1. Node* head = new Node(10); makes a heap node and stores its address.
    2. Create a (20) and b (30) the same way.
    3. (*head).next = a; links head to a; no & is needed because a is already an address.
    4. a->next = b; is the same thing written with the arrow.
    5. Print through head, head->next and head->next->next.
    Watch out. Heap nodes are never freed here. That is fine for a short demo, but long-running programs should delete nodes they no longer need.
    ✅ Check yourself: Why is head->next = a; correct but head->next = &a; wrong here?
    a is already a Node*; &a would be a Node**, the address of the pointer variable.

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>
using namespace std; // Allows us to avoid prefixing standard library objects with `std::`.

// Node class represents a single element in a linked list.
class Node {
    public:
        int val;     // Value stored in the node (data).
        Node* next;  // Pointer to the next node in the linked list.

        // Constructor for the Node class to initialize 'val' and set 'next' to NULL.
    Node(int val) {
        this->val = val;  // Assign the provided value to the 'val' member.
        this->next = NULL; // Initialize 'next' to NULL, meaning no next node by default.
    }
};

// Main function: Entry point of the program.
int main() {
    Node* head = new Node(10); // Create the first node and store its address in 'head'.
    Node* a = new Node(20);   // Create the second node and store its address in 'a'.
    Node* b = new Node(30);  // Create the third node and store its address in 'b'.
    Node* c = new Node(40);  // Create the fourth node and store its address in 'c'.


    head->next = a;
    a->next = b;
    b->next = c;

    Node* tmp = head;

    // This will not print the value of the last node
    while(tmp->next != NULL){
        cout << tmp->val << endl;
        tmp = tmp->next;
    }

    // Running the loop for second time
    tmp = head;

    // This will not print the value of the last node
    while(tmp->next != NULL){
        cout << tmp->val << endl;
        tmp = tmp->next;
    }

    // Now, let's also print the value of the last node
    while(tmp != NULL){
        cout << tmp->val << endl;
        tmp = tmp->next;
    }


    return 0;
}

    This program reads no input.

    Output 
    10

10

    Reading the output. 10 20 30 (loop 1), 10 20 30 (loop 2), then 40 (loop 3, starting where loop 2 stopped). Each value is on its own line.

    How it works, step by step
    1. Build 10 -> 20 -> 30 -> 40.
    2. Loop 1 runs while tmp->next != NULL: prints 10, 20, 30 and stops on node 40 without printing it.
    3. Reset tmp = head and repeat: again 10, 20, 30, and tmp is left on node 40.
    4. Loop 3 runs while tmp != NULL. It starts from node 40 (not from head), so it prints only 40.
    Watch out. Loop 3 does not reset tmp = head, so it is not a full print. To print the whole list, reset tmp first and use while (tmp != NULL).
    ✅ Check yourself: What condition prints every node, including the last?
    while (tmp != NULL).

    📌 Remember

    • A node = value + pointer to the next node; the last node points to NULL.
    • Use a constructor so next always starts as NULL.
    • p->x means (*p).x.
    • Create list nodes with new so they outlive the function.
    • Traverse with a copy of head: while (tmp != NULL) tmp = tmp->next;.

    ✅ Check yourself

    Why does a linked list use more memory than an array for the same values?
    Each node also stores a pointer (usually 8 bytes) alongside the value.
    What is the cost of reaching the k-th element in a linked list, and why?
    O(k): you must follow k links from the head; there is no direct indexing.
    Name two array limitations that linked lists solve.
    Fixed size decided up front, and slow insert/delete in the middle because elements must shift.
