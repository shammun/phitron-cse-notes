    Binary tree problems: views, levels, diameter, same tree

    This module is a problem-solving practice round on binary trees. Almost every solution is one of two tools: a recursive DFS that asks the left and right subtrees and combines their answers, or a BFS with a queue of (node, level) pairs that knows which level each node is on. Once you can pick the right tool, problems like left/right view, node level, diameter and same-tree become short.

    🧭 Start here

    This is a problem day, and the useful news is that nearly every binary tree problem is one of two shapes. Before you write anything, read the question and decide which one it is.

    Ask yourself: does the answer depend on where a node sits (its level, what you see from the side, the top row), or on what is inside a subtree (a value, a count, a height, a shape)? The first kind is a level-order walk with a queue. The second kind is a recursion that returns a value. Both run on the tree below.

            10
       /  \
     20    30
     /     / \
   40    50   60

    Shape one: walk the levels. Take the left view, meaning what you see standing to the left of the tree: the first node of every level. Level order already visits the levels in order, so the one thing you are missing is the level number of each node. Carry it in the queue with the node, as a pair: push {root, 1} and push each child as {child, level + 1}. Keep a small bool array of levels already seen, and the first node popped on a level is the answer for that level.

    Push the right child before the left one and exactly the same code prints 10 30 60, the right view. Node level, reverse level order and "all nodes on level X" are this same walk with a different rule at the moment you pop.

    pop (10,1)   level 1 new   -> keep 10
pop (20,2)   level 2 new   -> keep 20
pop (30,2)   seen          -> skip
pop (40,3)   level 3 new   -> keep 40
pop (50,3)   seen          -> skip
pop (60,3)   seen          -> skip

left view: 10 20 40

    Shape two: ask both children and combine. Write the function as if the two subtrees had already answered the question, and say how you would join their answers. The base case is almost always root == NULL.

    Looking for 50: 10 is not it, so ask the left side. 20 is not it, 40 is not it, so the left side reports false. The right side then finds 50 and reports true, and that true is passed back up to the top. || stops as soon as one side says true, so when the value sits on the left the right side is never searched.

    Same tree, univalued tree and root-equals-sum-of-children are the same shape with a different join: there both sides must agree, so you combine with && instead of ||.

    bool present(Node* root, int x){
    if(root == NULL) return false;
    if(root->val == x) return true;
    return present(root->left, x)
        || present(root->right, x);
}

    The diameter is the classic case of combining the two children, and it is worth doing slowly. The diameter is the longest path between any two nodes, counted in edges, and the trap is that this path does not have to pass through the root.

    So ask at every node. While a node computes its own height it already knows the height of its left side and the height of its right side; left + right is the length of the path that bends through this node. Keep the best value seen so far in a variable outside the function, and the answer is that best, not the value at the root.

    Here the root wins with 4, the path 40 - 20 - 10 - 30 - 50. On a lopsided tree the best bend often sits far below the root, which is the whole reason for updating everywhere.

    node   left h   right h   bend = l + r
 40       0        0          0
 20       1        0          1
 50       0        0          0
 60       0        0          0
 30       1        1          2
 10       2        2          4   <- best

    What to watch for on judges. The node class is not the Node you wrote at home: Code360 uses TreeNode<int>, LeetCode uses TreeNode, and these files have no main, so to run one locally you add a node class, a builder and a main yourself. Check root == NULL at the top of every function, because an empty tree is a legal input.

    Once you can name the shape in one sentence, these problems become six or eight lines each. The programs below go through both shapes several times, including one file that answers the right view where the left view was asked for, a good reminder to check which child you push first.

    💡 Key ideas

    Recursive combine

    Solve the problem for root->left and root->right, then combine the two answers at the root. The base case is almost always root == NULL.

    bool l = f(root->left);
bool r = f(root->right);
return l && r;

    BFS with levels

    Push {node, level} pairs into the queue. When you pop a node you know its level, and its children get level + 1.

    queue<pair<TreeNode*, int>> q;
q.push({root, 1});

    First node seen on a level

    In BFS, the first node you pop on each level is the leftmost one (if you push left before right). Mark levels you have already seen with a bool array to keep only that first node. Push right first and you get the right view instead.

    Diameter = best left height + right height

    The longest path through a node goes down its left side and down its right side. Compute heights recursively and, at every node, update a global maximum with l + r.

    Comparing two trees

    Two trees are the same if both are empty, or both roots have the same value and their left subtrees match and their right subtrees match. A shape difference (one is NULL, the other not) means different.

    Leaf sequence

    A DFS that visits left before right collects leaves from left to right. Two trees are leaf-similar when those lists are equal.

    STL pair

    pair<A, B> holds two values, read with .first and .second. It is what lets a queue store a node together with its level.

    pair<int,int> p = {2, 3};
cout << p.first;

#include <iostream>
#include <queue>
#include <utility>

class Solution {
public:
    vector<int> rightSideView(TreeNode* root) {
        vector<int> ans;
        bool freq[105] = {false};
        queue<pair<TreeNode*, int>> q;
        if(root){
            q.push({root, 1});
        }

        while(!q.empty()){
            pair<TreeNode*, int> parent = q.front();
            q.pop();

            TreeNode* node = parent.first;
            int level = parent.second;

            if(freq[level] == false){
                ans.push_back(node->val);
                freq[level] = true;
            }

            if(node->right){
                q.push({node->right, level + 1});
            }
            if(node->left){
                q.push({node->left, level + 1});
            }
        }
        return ans;
    }
};

/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:
    bool isUnivalHelper(TreeNode* root, int value){
        if(root == NULL){
            return true;
        }

        if(root->val != value){
            return false;
        }

        return isUnivalHelper(root->left, value) && isUnivalHelper(root->right, value);
    }

    bool isUnivalTree(TreeNode* root) {
        if(root == NULL){
            return true;
        }

        return isUnivalHelper(root, root->val);
    }
};

/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:

    void leafSequence(TreeNode* root, vector<int>& leaves){
        if(root == NULL){
            return;
        }

        if(root->left == NULL && root->right == NULL){
            leaves.push_back(root->val);
            return;
        }

        leafSequence(root->left, leaves);
        leafSequence(root->right, leaves);
    }

    bool leafSimilar(TreeNode* root1, TreeNode* root2) {
        vector<int> leaves1, leaves2;

        leafSequence(root1, leaves1);
        leafSequence(root2, leaves2);

        return leaves1 == leaves2;
    }
};

/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */

#include <iostream>
#include <vector>

class Solution {
public:
    void inorder(TreeNode* node, vector<int> & result){
        if(node == NULL){
            result.push_back(-1001);
            return;
        }
        result.push_back(node->val);
        inorder(node->left, result);
        inorder(node->right, result);
    }

    bool isSameTree(TreeNode* p, TreeNode* q) {
        vector<int> result1;
        vector<int> result2;

        inorder(p, result1);
        inorder(q, result2);

        return result1 == result2;
    }
};

class Solution {
public:
    bool isSameTree(TreeNode* p, TreeNode* q) {

        if(p == NULL && q == NULL){
            return true;
        }
    
        if(p == NULL || q == NULL){
            return false;
        }

        return p->val == q->val && isSameTree(p->left, q->left) && isSameTree(p->right, q->right);
    }
};

    📌 Remember

    • Most tree problems are either "ask both subtrees and combine" (DFS) or "walk level by level" (BFS).
    • Store {node, level} pairs in the queue whenever the answer depends on the level.
    • Left view = first node per level with left pushed first; right view = push right first.
    • Diameter: update a global best with left height + right height at every node.
    • Two trees are equal when both are NULL, or values match and both pairs of subtrees match.
    • Judge solutions have no main; to test locally, add a node class, a tree builder and a main.
