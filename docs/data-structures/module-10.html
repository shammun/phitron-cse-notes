    🧭 Start here

    Stand five people in a row, each one pointing at the person in front. That is a linked list: the only way onward is the finger you are standing at, and there is no way back. Now make everybody point the other way.

    The lazy answer is to copy the values into a vector and write them back in reverse. It works, it costs a second array, and the chain itself is untouched — you have only relabelled the people. This module turns the arrows.

    Turning one arrow is one line, curr->next = prev. The trouble comes the instant you write it: curr->next was the only way to the rest of the list, and now it is gone. So you keep three fingers on the list — prev for the part already turned, curr for the node you are turning, nxt holding the rest before you cut it. Each step turns one arrow and slides all three along. For 10 20 30:

    start   NULL    10 -> 20 -> 30 -> NULL
        prev   curr

step 1  NULL <- 10    20 -> 30 -> NULL
               prev  curr

step 2  NULL <- 10 <- 20    30 -> NULL
                     prev  curr

step 3  NULL <- 10 <- 20 <- 30    NULL
                           prev  curr

curr is NULL, so stop.  new head = prev = 30

    prev starts at NULL on purpose: the old head becomes the new tail, and a tail points at nothing. When curr falls off the end, prev is standing on the old last node, and that is your new head.

    Node* prev = NULL;
Node* curr = head;
while(curr != NULL){
    Node* nxt = curr->next;   // hold the rest
    curr->next = prev;        // turn one arrow
    prev = curr;              // slide both fingers
    curr = nxt;
}
head = prev;                  // the old last node

    What is new here. Every list walk so far only read nodes: print them, count them, compare them. This walk changes the shape of the list while you stand inside it, so the order of those four lines is the whole problem. Move prev = curr up a line and the rest of the chain is lost.

    The program on the page does the same turning with recursion instead of a loop. It walks down to the last node, makes that the head, and on the way back each call turns one arrow with temp->next->next = temp; then cuts the old one with temp->next = NULL;.

    A doubly linked list needs none of this. Since every node knows the one behind it, put a pointer at head and one at tail, swap the two values and move both inwards until they meet or cross. Turn the swap into a comparison and the same walk answers "is this list a palindrome".

    The second idea answers a different question: does this chain ever end? If a node points back at an earlier node there is no NULL anywhere, and an ordinary traversal runs for ever.

    The obvious check is to remember every node you have stood on and compare each new one against all of them: O(n²) comparisons and an array of addresses. Two pointers do it in O(n) with no extra memory.

    Picture two runners. slow moves one node per step, fast two. If the track is a road, fast reaches the end and there is no cycle. If it is a loop there is no end, so both runners end up inside the loop, and from then on fast closes the gap by exactly one node each step. A gap that shrinks by one cannot step over zero, so fast must land on the node slow is on. For 10 20 30 40 50 with 50 pointing back at 20:

    step   slow   fast
  0     10     10    both start at the head
  1     20     30
  2     30     50
  3     40     30    fast has gone round
  4     50     50    same node, so a cycle

    Move first, compare afterwards. The file here compares before the first move, while both pointers are still on the head, so it reports a cycle for any list of two or more nodes; the note under it gives the fix. Stop that same walk when fast runs out, and slow is standing exactly on the middle node.

    The last part of the module is a relief. Everything you built by hand is already in C++ as std::list: push_front, pop_back, sort, unique, remove and reverse are one call each. What you do not get is l[2] — a linked list cannot jump to an index, so you move an iterator with next(it, 2) and pay for the walk. Writing it yourself is what makes that price obvious.

    💡 Key ideas

    Recursive reversal of a singly list

    Recurse to the last node and make it the new head. While returning, each node makes its next node point back at it (temp->next->next = temp) and clears its own next.

    rev(temp->next);
temp->next->next = temp;
temp->next = NULL;

    Two-pointer reversal of a doubly list

    Put i at the head and j at the tail, swap their values, and move them towards each other. Stop when they meet (odd length) or cross (i->prev == j, even length).

    for(i=head, j=tail; i!=j && i->prev!=j; i=i->next, j=j->prev) swap(i->val, j->val);

    Palindrome check

    Same two pointers as the reversal, but compare instead of swap. One mismatch means the list is not a palindrome.

    Floyd's cycle detection

    slow moves one step and fast moves two. If there is a loop, fast eventually lands on slow; if not, fast reaches NULL. Move first, then compare, because both start at the head.

    while(fast && fast->next){ slow=slow->next; fast=fast->next->next; if(slow==fast) return true; }

    std::list basics

    list<int> is a doubly linked list. It has O(1) push_front, push_back, pop_front, pop_back, front(), back(), size() and empty(). There is no []; use iterators.

    list<int> l = {1, 2, 3};

    Iterators and next

    l.begin() points to the first element; l.end() points one past the last, so the last element is *prev(l.end()) or *(--l.end()). next(l.begin(), i) walks i steps and takes O(i).

    cout << *next(l.begin(), 2);

    Insert and erase by position

    l.insert(it, value) or l.insert(it, first, last) puts values before it. l.erase(it) removes one element; l.erase(a, b) removes the half-open range [a, b).

    List operations

    remove(v) deletes every v; sort() sorts (pass greater<int>() for descending); unique() removes adjacent duplicates, so sort first; reverse() flips the order. find and replace come from <algorithm>.

    l.sort(); l.unique();

    Reading the output. Under "Before reversing" you see 10 20 30 40; under "After reversing" you see 40 30 20 10 — the links really changed, not just the printing order.

    How it works, step by step
    1. reverse_linked_list(head, tail, head) recurses down with temp->next.
    2. Base case: at the last node (temp->next == NULL), set head = temp — the old last node is the new head.
    3. While returning, temp->next->next = temp turns the link around.
    4. temp->next = NULL cuts the old forward link, and tail = temp; the final return leaves the old head as tail.
    5. For 10 20 30 40: 40 becomes head, then 40→30, 30→20, 20→10, and 10→NULL.
    Watch out. An empty list crashes, because temp->next is read when temp is NULL. Check head == NULL before calling.
    ✅ Check yourself: Why is temp->next = NULL needed after flipping the link?
    Otherwise the old head still points forward, making a two-node cycle at the end of the list.

void delete_at_head(Node* &head, Node* & tail){
    if(head==NULL){
        return;
    }
    if(head->next == NULL){
        delete head;
        // head = NULL; 
        // setting head = NULL is not needed after we delete the head, it will be automatically 
        // null but setting head to NULL is a good practice and it will make the code more 
        // readable there is no harm in setting head to NULL after deleting the head
        
        tail = NULL;
        return;
    }
    Node* deleteNode = head;
    head = head->next;
    head->prev = NULL;
    delete deleteNode;
}

void delete_at_tail(Node* &head, Node* &tail){

    if(head == tail){
        delete deleteNode;
        head = NULL;
        tail = NULL; // this line is not necessary because tail will be 
        //automatically null after deleting the tail
        return;
    }
    tail = tail->prev;
    tail->next = NULL;
    delete deleteNode;
}

void delete_at_any_position(Node* &head, Node* &tail, int pos){
    if(pos == 0){
        delete_at_head(head, tail);
        return;
    }

    for(int i=1; i<pos; i++){

void swap(int &a, int &b){
    int temp = a;
    a = b;
    b = temp;
}


void reverse_doubly(Node* &head, Node* &tail){
    for(Node *i=head, *j=tail; i!=j && i->prev != j; i=i->next,j=j->prev){
        swap(i->val, j->val);
    }
}

    📌 Remember

    • Recursive reversal: recurse first, then temp->next->next = temp; temp->next = NULL;.
    • Two pointers from both ends reverse or palindrome-check a doubly list; stop on meet or cross.
    • Floyd's cycle check: move slow by 1 and fast by 2, then compare.
    • std::list is a doubly linked list: O(1) at the ends, no [], use next(it, i).
    • end() is one past the last element — never dereference it.
    • sort() before unique(); remove(v) deletes every copy of v.

    ✅ Check yourself

    What is the extra space cost of the recursive singly-list reversal, and how could you avoid it?
    O(n) for the call stack; an iterative version with prev, curr and next pointers uses O(1).
    Why can't std::sort be used on a std::list?
    std::sort needs random-access iterators; a list only has bidirectional ones, so it provides its own l.sort().
    In cycle detection, why must the pointers move before they are compared?
    They both start at the head, so comparing first would always find them equal and wrongly report a cycle.
    What does l.insert(l.begin(), 5) do?
    It inserts 5 before the first element — the same as push_front(5).
