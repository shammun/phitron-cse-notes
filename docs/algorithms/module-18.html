    Introduction to Algorithms · Module 18

    Merge sort, LCS and Kruskal's MST

    Three classic algorithms close the course. Merge sort shows divide and conquer: split the array in half, sort each half, merge them. Longest common subsequence is a two-string DP. Kruskal's algorithm builds a minimum spanning tree by taking the cheapest edges that do not form a cycle, using DSU. The module's quiz material also contrasts substrings with subsequences.

    🧭 Start here

    Hand a friend half of an unsorted pile of exam papers, keep the other half, and you both sort your own half. Now two sorted piles lie face up on the table. Joining them is easy: look at the top paper of each pile, take the smaller roll number, repeat. You never look deeper than the top card.

    That joining step is the merge, and it is the only clever part of merge sort. Two sorted halves going in:

    left  : 2 5 9        right : 1 6 8

compare      take     result so far
2 vs 1        1       1
2 vs 6        2       1 2
5 vs 6        5       1 2 5
9 vs 6        6       1 2 5 6
9 vs 8        8       1 2 5 6 8
left over     9       1 2 5 6 8 9

    Every number is copied exactly once, so merging two halves holding n numbers between them costs about n steps.

    And if you have no friend? Split your half again, and again, until each pile holds one paper — a pile of one is already sorted. Eight papers split 8, 4, 2, 1: three rounds, and log2 of n rounds in general. Each round merges everything once, about n steps, so the whole sort is O(n log n). For a million numbers that is roughly 20 million steps, where the compare-everything-with-everything sorts of earlier modules would need a million million.

    void divide(int a[], int l, int r){
    if(l >= r) return;       // one element, already sorted
    int mid = (l + r) / 2;
    divide(a, l, mid);       // sort the left half
    divide(a, mid+1, r);     // sort the right half
    conquer(a, l, mid, r);   // merge the two sorted halves
}

    The second topic is a different animal. The word cat sits inside cart if you may skip letters: c, a, jump over r, then t. That is a subsequence. A substring would have to be a solid block, and cat is not a solid block of cart. The longest common subsequence of two strings is the longest skipping match they share.

    Lay the two words out as a table, one down the side and one along the top. Each cell holds the answer for the two prefixes meeting there. If the two letters match, take the cell diagonally up-left and add 1. If they do not match, take the larger of the cell above and the cell to the left — that is "drop a letter from one string or the other, and keep the better result".

              ""   c   a   t
   ""      0   0   0   0
   c       0   1   1   1
   a       0   1   2   2
   r       0   1   2   2
   t       0   1   2   3   <- answer

3 letters in common, and they spell "cat"

    Notice the row for r: it matches nothing, so it simply copies the row above. That is the skipped letter.

    The third topic joins villages with cable. You know the price of every possible cable and want every village connected for the least money. The rule is almost too simple: sort the cables cheapest first, and lay one only if the two villages it joins are not already connected through cables you have laid. If they are, that cable makes a loop — money spent, nothing new reached.

    "Already connected to each other" is exactly the question Module 11 answered: find(a) == find(b) in a disjoint set union. Kruskal's algorithm is nothing more than that DSU checking a sorted edge list as it goes past. Four villages:

    edge  cost  groups before      take it?
1-2    1    {1}{2}{3}{4}       yes -> {1,2}
2-3    2    {1,2}{3}{4}        yes -> {1,2,3}
1-3    3    {1,2,3}{4}         no, same group
3-4    4    {1,2,3}{4}         yes -> {1,2,3,4}
1-4    5    {1,2,3,4}          no, same group

total cost = 1 + 2 + 4 = 7, using 3 edges

    Three edges for four nodes, and that is no accident: a tree that spans n nodes always has exactly n-1 edges. Taking the cheapest edge that is still safe, every time, gives the smallest possible total — which is why this one is called the minimum spanning tree.

    💡 Key ideas

    Divide and conquer

    Break the problem into halves, solve each half recursively, then combine. For merge sort the combining step is the merge.

    Merging two sorted arrays

    Keep one pointer in each array, copy the smaller front element, advance that pointer, and finally copy whatever is left.

    while (i < n && j < m) c[k++] = (a[i] < b[j]) ? a[i++] : b[j++];

    Merge sort cost

    log n levels of halving, and each level does O(n) merge work, so O(n log n) time with O(n) extra memory.

    Substring vs subsequence

    A substring is a contiguous block of characters. A subsequence keeps the order but may skip characters. ace is a subsequence of abcde, not a substring.

    LCS recurrence

    Compare the last characters: equal gives 1 + lcs of both shorter strings; different gives the better of dropping one character from either string.

    if (a[i] == b[j]) return 1 + lcs(i-1, j-1);
return max(lcs(i-1, j), lcs(i, j-1));

    Minimum spanning tree

    A set of n-1 edges that connects all nodes with the smallest total weight and no cycle.

    Kruskal's algorithm

    Sort edges by weight. Walk through them and keep an edge only if its ends are in different DSU groups; then union them.

    How it works, step by step

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>

using namespace std;

void conquer(int c[], int l, int mid, int r){
    int n = mid - l + 1;
    int a[n];
    for(int i=0; i<n; i++){
        a[i] = c[l+i];
    }

    int m = r - mid;
    int b[m];
    for(int i=0; i<m; i++){
        b[i] = c[mid+1+i];
    }

    // Now, take the two pointers for the two arrays and pointer for the result array
    int i=0, j=0, curr=l;

    while(i < n && j < m){
        if(a[i] < b[j]){
            c[curr] = a[i];
            i++;
            curr++;
        } else{
            c[curr] = b[j];
            j++;
            curr++;
        }
    }

    while(i < n){
        c[curr] = a[i];
        i++;
        curr++;
    }

    while(j < m){
        c[curr] = b[j];
        j++;
        curr++;
    }
}

void divide(int a[], int l, int r){ // O(nlogn) -- this does the merge sort
    if(l >= r){
        return;
    }
    int mid = (l+r)/2;
    divide(a, l, mid); // merge sort the left half
    divide(a, mid+1, r); // merge sort the right half
    conquer(a, l, mid, r); // merge the two sorted arrays
}

int main(){
    // First we will take the input for two arrays

    int n, m;
    cin >> n >> m;

    int a[n];
    for(int i=0; i<n; i++){
        cin >> a[i];
    }

    divide(a, 0, n-1);

    for(int i=0; i<n; i++){
        cout << a[i] << " ";
    }

    return 0;
}

    6 0
5 2 9 1 5 6

    n and an unused m, then n values (a duplicate 5 is included).

    1 2 5 5 6 9

    Reading the output. Prints 1 2 5 5 6 9. Duplicates are kept.

    How it works, step by step
    1. divide(a, l, r): return if the range has one element.
    2. Sort [l, mid] and [mid+1, r] recursively.
    3. conquer copies the two halves into temporary arrays a and b.
    4. It merges them back into c[l..r] with the two-pointer method.
    5. main prints the sorted array.
    Watch out. main still reads an unused m, left over from conquer.cpp; the input must contain it. Using a[i] <= b[j] in the merge would make the sort stable (equal values keep their order).
    ✅ Check yourself: Why is merge sort always O(n log n), even on already-sorted input?
    It always splits in the middle and always merges, whatever the order of the values.

    // Longest common substring using recursion
// We will be given two strings a and b. We have to find the length of the 
// longest common substring of the two strings.
// We will use memoization to optimize the solution.


#include <iostream>
#include <vector>
#include <algorithm>
#include <string>

using namespace std;
string a, b;
int dp[1005][1005];

int lcs(int i, int j){
    if(i < 0 || j < 0){
        return 0;
    }

    if(dp[i][j] != -1){
        return dp[i][j];
    }

    if(a[i] == b[j]){
        dp[i][j] = lcs(i-1, j-1) + 1;
        return dp[i][j];
    } else{
        int op1 = lcs(i-1, j);
        int op2 = lcs(i, j-1);
        dp[i][j] = max(op1, op2);
        return dp[i][j];
    }
}

int main(){
    memset(dp, -1, sizeof(dp));
    cin >> a >> b;
    int n = a.size();
    int m = b.size();
    cout << lcs(n-1, m-1);

    return 0;
}
    Input (stdin)
    abcde
ace

    Two strings.

    Output 
    3

    Reading the output. Prints 3 (the common subsequence ace).

    How it works, step by step
    1. memset(dp, -1, ...) and read strings a, b.
    2. Base case: an empty prefix (i < 0 or j < 0) gives 0.
    3. If a[i] == b[j], the answer is lcs(i-1, j-1) + 1.
    4. Otherwise the best of skipping a[i] or skipping b[j].
    5. Print lcs(n-1, m-1).
    Watch out. The top comment says 'substring', but the code computes the longest common subsequence; a substring version would reset to 0 when characters differ. Tip: on some compilers you need #include <cstring> for memset; this file relies on another header bringing it in.
    ✅ Check yourself: What is the LCS length of abc and def?
    0, they share no characters.

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>

using namespace std;

int par[1005];
int group_size[1005];

class Edge{
    public:
        int a, b, c;
        Edge(int a, int b, int c){
            this->a = a;
            this->b = b;
            this->c = c;
        }
};

bool cmp(Edge l, Edge r){
    return l.c < r.c;
}

int find(int node){
    if(par[node] == -1){
        return node;
    }
    int leader = find(par[node]);
    par[node] = leader;
    return leader;
}

int dsu_union(int node1, int node2){
    int leader1 = find(node1);
    int leader2 = find(node2);

    if(group_size[leader1] >= group_size[leader2]){
        par[leader2] = leader1;
        group_size[leader1] += group_size[leader2];
    } else{
        par[leader1] = leader2;
        group_size[leader2] += group_size[leader1];
    }
}

int main(){
    memset(par, -1, sizeof(par));
    memset(group_size, 1, sizeof(group_size));

    int n, e;
    cin >> n >> e;
    vector<Edge> edge_list;

    while(e--){
        int a, b, c;
        cin >> a >> b >> c;
        edge_list.push_back(Edge(a, b, c));
    }

    sort(edge_list.begin(), edge_list.end(), cmp);

    /*
    for(auto edge : edge_list){
        cout << edge.a << " " << edge.b << " " << edge.c << endl;
    }
    */
    
    int total_cost = 0;

    // Check if the edges are connected or not
    for(auto edge : edge_list){
        int parA = find(edge.a);
        int parB = find(edge.b);
        if(parA != parB){
            dsu_union(edge.a, edge.b);
            total_cost += edge.c;
        }
    }

    cout << total_cost << endl;

    return 0;
}

    4 5
1 2 1
2 3 4
1 3 3
3 4 2
1 4 5

    Reading the output. The program crashes before printing anything (status exit_0xc0000005, an access violation), and the compiler warns no return statement in function returning non-void. That missing return is the cause (see Watch out). With the fix it prints 6: edges 1-2 (1), 3-4 (2) and 1-3 (3).

    How it works, step by step
    1. Read the edges into edge_list as Edge(a, b, c).
    2. sort them with cmp, cheapest first.
    3. For each edge, find the leaders of both ends.
    4. Different leaders: dsu_union them and add the weight to total_cost.
    5. Same leader: skip it, it would form a cycle.
    6. Print total_cost.
    Watch out. dsu_union is declared to return int but never returns anything. In C++ that is undefined behaviour, and here it makes the program crash on the first union. Make it void dsu_union(...). Also, memset(group_size, 1, ...) fills bytes, not ints; set sizes with a loop. If the graph may be disconnected, also count kept edges and check that there are n-1. Tip: on some compilers you need #include <cstring> for memset.
    ✅ Check yourself: Why is it safe to skip an edge whose ends already share a leader?
    Its ends are already connected by cheaper (or equal) edges, so adding it would only create a cycle and raise the cost.

    /*

Sort an Array   (LeetCode 912)

Given an array of integers, return it sorted in increasing order. The
built-in sort is not allowed, so this is the module's own merge sort:
split the array in half, sort each half by the same routine, then merge
the two sorted halves in one walk.

Constraints
    1 <= nums.length <= 5 * 10^4
    -5 * 10^4 <= nums[i] <= 5 * 10^4

Input (for the small driver below)
    first line: n, the number of values
    second line: the n values

Output
    sorted = the values in increasing order, separated by spaces

Example 1

input
4
5 2 3 1

output
sorted = 1 2 3 5

Example 2

input
6
5 1 1 2 0 0

output
sorted = 0 0 1 1 2 5

    Equal values stay next to each other; merge sort keeps them in order
    because the merge takes from the left half when the two fronts tie.

*/

#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    // Both halves a[l..mid] and a[mid+1..r] are already sorted.
    // Copy them out and write the smaller front back into a, one at a time.
    void conquer(vector<int>& a, int l, int mid, int r) {
        vector<int> left(a.begin() + l, a.begin() + mid + 1);
        vector<int> right(a.begin() + mid + 1, a.begin() + r + 1);

        int i = 0, j = 0, curr = l;

        while (i < (int)left.size() && j < (int)right.size()) {
            // <= and not <, so that equal values keep their original order.
            if (left[i] <= right[j]) {
                a[curr] = left[i];
                i++;
            } else {
                a[curr] = right[j];
                j++;
            }
            curr++;
        }

        // One side may still have leftovers; they are already in order.
        while (i < (int)left.size()) {
            a[curr] = left[i];
            i++;
            curr++;
        }
        while (j < (int)right.size()) {
            a[curr] = right[j];
            j++;
            curr++;
        }
    }

    void divide(vector<int>& a, int l, int r) { // O(n log n)
        // One value (or none) is already sorted, so there is nothing to do.
        if (l >= r) {
            return;
        }

        int mid = (l + r) / 2;
        divide(a, l, mid);          // sort the left half
        divide(a, mid + 1, r);      // sort the right half
        conquer(a, l, mid, r);      // merge the two sorted halves
    }

    vector<int> sortArray(vector<int>& nums) {
        divide(nums, 0, (int)nums.size() - 1);
        return nums;
    }
};

int main() {
    int n;
    cin >> n;

    vector<int> nums(n);
    for (int i = 0; i < n; i++) {
        cin >> nums[i];
    }

    Solution sol;
    vector<int> ans = sol.sortArray(nums);

    cout << "sorted =";
    for (int i = 0; i < (int)ans.size(); i++) {
        cout << " " << ans[i];
    }
    cout << endl;

    return 0;
}

    4
5 2 3 1

    n, then the n values. The first sample of the problem.

    Output 
    sorted = 1 2 3 5

    Reading the output. Prints sorted = 1 2 3 5. On 6\n5 1 1 2 0 0\n it prints sorted = 0 0 1 1 2 5.

    How it works, step by step
    1. divide(a, l, r) stops when l >= r: one value is already sorted.
    2. Otherwise split at mid = (l + r) / 2, sort l..mid and mid+1..r by the same call, then merge them.
    3. conquer copies the two halves into left and right, then walks all three with one pointer each, always writing the smaller front value back into a.
    4. When one side runs out, the rest of the other side is copied over: it is already in order.
    5. The comparison is left[i] <= right[j], so equal values are taken from the left half first and keep their original order.
    6. sortArray just calls divide over the whole vector and returns it.
    Watch out. The left half is mid - l + 1 values and the right half is r - mid, not the same count when the range has an odd length. Slicing with a.begin() + l to a.begin() + mid + 1 gets both sizes right without any arithmetic.
    ✅ Check yourself: Why does merge sort cost O(n log n) rather than O(n^2)?
    Halving the range only takes log n levels, and each level merges every value exactly once, which is n work per level.

    /*

Road Reparation   (CSES 1675)

There are n cities and m roads. Repairing a road costs some amount, and a
repaired road can be used in both directions. Repair the cheapest set of
roads such that every city can be reached from every other city, and print
what that costs. If no set of roads can join all the cities, print
IMPOSSIBLE.

Keeping every city reachable with the smallest total cost is exactly a
minimum spanning tree, so this is Kruskal's algorithm from this module:
sort the roads by cost and take a road whenever its two cities are still in
different groups, using DSU to tell the groups apart.

Constraints
    1 <= n <= 10^5
    1 <= m <= 2 * 10^5
    1 <= a, b <= n
    1 <= c <= 10^9

Because 10^5 roads can each cost 10^9, the total does not fit in an int.
Keep it in a long long.

Input
    first line: n and m
    next m lines: a b c, a road between cities a and b costing c

Output
    the smallest total cost, or IMPOSSIBLE

Example

input
5 6
1 2 3
2 3 5
2 4 2
3 4 8
5 1 7
5 4 4

output
14

    Sorted by cost the roads are 2-4 (2), 1-2 (3), 5-4 (4), 2-3 (5),
    5-1 (7), 3-4 (8). The first four are taken and already join all five
    cities: 2 + 3 + 4 + 5 = 14. The last two would close a cycle, so they
    are skipped.

Example

input
3 1
1 2 5

output
IMPOSSIBLE

    City 3 has no road at all, so it can never be reached.

*/

#include <bits/stdc++.h>
using namespace std;

vector<int> par;
vector<int> group_size;

class Edge {
    public:
        int a, b, c;
        Edge(int a, int b, int c) {
            this->a = a;
            this->b = b;
            this->c = c;
        }
};

bool cmp(Edge l, Edge r) {
    return l.c < r.c;
}

int find(int node) {
    if (par[node] == -1) {
        return node;
    }
    // Point the node straight at its leader, so the next find is short.
    int leader = find(par[node]);
    par[node] = leader;
    return leader;
}

void dsu_union(int node1, int node2) {
    int leader1 = find(node1);
    int leader2 = find(node2);

    // Hang the smaller group under the bigger one to keep the tree flat.
    if (group_size[leader1] >= group_size[leader2]) {
        par[leader2] = leader1;
        group_size[leader1] += group_size[leader2];
    } else {
        par[leader1] = leader2;
        group_size[leader2] += group_size[leader1];
    }
}

int main() {
    int n, m;
    cin >> n >> m;

    par.assign(n + 1, -1);
    group_size.assign(n + 1, 1);

    vector<Edge> edge_list;
    for (int i = 0; i < m; i++) {
        int a, b, c;
        cin >> a >> b >> c;
        edge_list.push_back(Edge(a, b, c));
    }

    // Cheapest road first: that is the whole idea of Kruskal's algorithm.
    sort(edge_list.begin(), edge_list.end(), cmp);

    long long total_cost = 0;
    int taken = 0;

    for (int i = 0; i < (int)edge_list.size(); i++) {
        Edge edge = edge_list[i];
        int parA = find(edge.a);
        int parB = find(edge.b);

        // Same leader means the two cities are already joined, so this road
        // would only close a cycle and add cost for nothing.
        if (parA != parB) {
            dsu_union(edge.a, edge.b);
            total_cost += edge.c;
            taken++;
        }
    }

    // A tree over n cities needs exactly n-1 roads. Fewer means the roads
    // left the cities in two or more separate pieces.
    if (taken != n - 1) {
        cout << "IMPOSSIBLE" << endl;
    } else {
        cout << total_cost << endl;
    }

    return 0;
}
    Input (stdin)
    5 6
1 2 3
2 3 5
2 4 2
3 4 8
5 1 7
5 4 4

    n and m, then m lines a b c: a road between cities a and b costing c.

    Output 
    14

    Reading the output. Prints 14. Sorted by cost the roads are 2-4 (2), 1-2 (3), 5-4 (4), 2-3 (5), 5-1 (7), 3-4 (8); the first four join all five cities and add up to 14, the last two would close cycles. On 3 1\n1 2 5\n it prints IMPOSSIBLE, because city 3 has no road.

    How it works, step by step
    1. Read the m roads into a vector<Edge> and sort them by cost with the cmp comparator.
    2. DSU starts with par all -1 (every city is its own leader) and group_size all 1.
    3. Walk the sorted roads. If find(a) != find(b) the two cities are still in different pieces, so take the road: union them, add the cost, and count it.
    4. If the leaders are already the same, skip the road: it would only close a cycle and cost money for nothing.
    5. find sets par[node] = leader on the way back (path compression) and dsu_union hangs the smaller group under the bigger one, which keeps the trees flat.
    6. At the end a tree over n cities must have exactly n-1 roads. If fewer were taken, the roads left the map in two or more pieces, so print IMPOSSIBLE.
    Watch out. Two traps the module's file has. total_cost must be a long long: 10^5 roads at 10^9 each overflow an int. And the module's file uses memset(group_size, 1, sizeof(group_size)), which fills each byte with 1, not each int; assign(n + 1, 1) says what was meant.
    ✅ Check yourself: Why is counting the taken roads enough to spot a disconnected map?
    Kruskal takes a road only when it joins two different pieces, so each taken road drops the number of pieces by one. Starting from n pieces, ending with one needs exactly n-1 of them.

    • Merge sort = split in half, sort both halves, merge with two pointers: O(n log n).
