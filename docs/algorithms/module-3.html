    Introduction to Algorithms · Module 3

    DFS, grids and connected components

    This module adds depth-first search, which goes as deep as possible before backing up, written with recursion. It then moves both BFS and DFS onto 2D grids, where each cell is a node, and uses DFS to count connected components and their sizes.

    9 programs2 practice linksFolder on GitHub ↗

    🧭 Start here

    Think about walking through an unfamiliar building. BFS was the careful way: check every room next to the entrance, then every room next to those. Depth-first search is the way a person actually does it. Take the first door you have not been through, walk into that room, take the first door there, and keep going until you reach a room with nothing new. Then step back one room and try its next door.

    That is the whole algorithm, and it is recursion, which you already know: mark the room you are in, then call the same function on each unvisited neighbour. The call stack is what remembers the way back, so there is no queue at all.

    It is also the tree traversal you have written before. Pre-order printed a node, then went all the way down the left branch before touching the right one. DFS on a graph is pre-order with adj_list[src] instead of left and right, plus the vis array, because a graph, unlike a tree, can lead you back to where you started.

    void dfs(int src){
    cout << src << " ";
    vis[src] = true;
    for(int child : adj_list[src]){
        if(!vis[child]) dfs(child);
    }
}

    Take the graph of the first program below: node 0 joins 1 and 2, node 1 joins 3 and 4, node 2 joins 5. Start dfs(0) and follow the calls, with each level of indentation being one call deeper:

    dfs(0)  print 0
  dfs(1)  print 1
    dfs(3)  print 3   nothing new, return
    dfs(4)  print 4   nothing new, return
  back in 1, done, return
  dfs(2)  print 2
    dfs(5)  print 5   return

visit order:  0 1 3 4 2 5

    Compare that with BFS on the same graph, which would print 0 1 2 3 4 5. DFS finished the whole branch under 1 before it even looked at 2. Same graph, same neighbours, different order, and that difference matters: BFS hands you the shortest distance, DFS does not. DFS finds *a* path to a node, not the shortest one.

    The second new idea is that a grid is a graph. A 2D array of characters does not look like dots and lines, but treat cell (i, j) as a node whose neighbours are the four cells up, down, left and right, and every program from the last module works on it unchanged. The four steps are kept in a small list of {di, dj} pairs, and each neighbour is checked with valid(i, j) first: a cell on the top row has no cell above it, and reading grid[-1][j] is a bug waiting to happen.

    vector<pair<int,int>> direction = {{0,1},{0,-1},{-1,0},{1,0}};
int ci = si + direction[i].first;
int cj = sj + direction[i].second;
if(valid(ci, cj) && !vis[ci][cj]) dfs(ci, cj);

    DFS on an open 2 by 3 grid, starting at the top-left with the directions tried in the order right, left, up, down, moves like a snake. The numbers show the order the cells are entered:

    grid          order entered
 .  .  .       1   2   3
 .  .  .       6   5   4

    It runs right until the edge of the grid stops it, drops down, then comes back along the bottom row. Change the order of the direction list and the picture changes, because DFS takes the first direction that works and commits to it.

    The third idea is counting the pieces. A graph can be in several disconnected parts, like islands with no bridge between them, and one DFS paints exactly one island: it reaches only what is joined to its starting node. So walk over all n nodes, and every time you find one still unvisited, start a DFS there and add one to a counter. With 9 nodes split into {0,1,2,3}, {4,5} and {6,7,8} the loop starts a DFS at 0, then at 4, then at 6, so the answer is 3. The loop must cover every node, because a node with no edges is still an island of its own. For the size of each piece, set a counter to 0 just before the call and add 1 inside dfs for every node it enters.

    The programs below work through all of it: DFS on a graph, BFS and DFS on grids with and without walls, counting components, component sizes, and a flood fill that repaints a picture.

    💡 Key ideas

    DFS with recursion

    Mark the node, then call dfs on each unvisited neighbour. The call stack remembers where to come back to.

    void dfs(int u){
  vis[u] = true;
  for(int v : adj[u]) if(!vis[v]) dfs(v);
}

    Grid as a graph

    Cell (i, j) is a node. Its neighbours are the 4 cells up, down, left and right, taken from a direction list of {di, dj} pairs.

    valid(i, j)

    Before touching a neighbour, check it is inside the grid: 0 <= i < n and 0 <= j < m. Then check it is not visited and not a wall.

    Connected components

    Loop over every node; each time you find an unvisited one, start a DFS and add 1 to the count. Each DFS paints one whole piece.

    Component size

    Reset a counter before each DFS and increment it inside dfs; after the call it holds that component's size.

    Flood fill

    DFS on a grid that changes cell values as it goes, e.g. recolour every connected pixel of the same colour.

    #include <iostream>
#include <vector>
#include <algorithm>    
#include <string>
#include <stack>
#include <queue>

using namespace std;

vector<int> adj_list[1005];
bool vis[1005];

void dfs(int src){
    cout << src << " ";
    vis[src] = true;

    for(int child : adj_list[src]){
        if(!vis[child]){
            dfs(child);
        }
    }
}

int main(){
    int n, e;
    cin >> n >> e;

    while(e--){
        int a, b;
        cin >> a >> b;
        adj_list[a].push_back(b);
        adj_list[b].push_back(a);
    }
    memset(vis, false, sizeof(vis));
    dfs(0);

    return 0;
}

0 1
0 2
1 3
1 4
2 5

    n e, then edges. Tree: 0 has children 1 and 2; 1 has 3 and 4; 2 has 5.

    Output 
    0 1 3 4 2 5

    Reading the output. 0 1 3 4 2 5: the whole branch under 1 is finished before 2 is visited (BFS would print 0 1 2 3 4 5).

    How it works, step by step
    1. Build the undirected adjacency list.
    2. dfs(src) prints src and marks it visited.
    3. For each unvisited child, call dfs(child) right away: go deep first.
    4. When all children are done, the function returns to its caller (backtracking).
    Watch out. Tip: on some compilers you need #include <cstring> for memset; this file relies on another header bringing it in.

    #include <iostream>
#include <vector>
#include <algorithm>    
#include <string>
#include <stack>
#include <queue>

using namespace std;

char grid[105][105];
bool vis[105][105];
int level[105][105];
vector<pair<int, int>> direction = {{0, 1}, {0, -1}, {-1, 0}, {1, 0}};
int n, m;

bool valid(int i, int j){
    if(i < 0 || i >= n || j < 0 || j >= m){
        return false;
    }
    return true;
}

void bfs(int si, int sj){
    queue<pair<int, int>> q;
    q.push({si, sj});
    vis[si][sj] = true;
    level[si][sj] = 0;

    while(!q.empty()){
        pair<int, int> par = q.front();
        q.pop();
        int par_i = par.first;
        int par_j = par.second;

        for(int i=0; i<4; i++){
            int ci = par_i + direction[i].first;
            int cj = par_j + direction[i].second;
            if(valid(ci, cj) == true && vis[ci][cj] == false){
                q.push({ci, cj});
                vis[ci][cj] = true;
                level[ci][cj] = level[par_i][par_j] + 1;
            }
        }
    }
}

int main(){
    cin >> n >> m;
    for(int i=0; i<n; i++){
        for(int j=0; j<m; j++){
            cin >> grid[i][j];
        }
    }

    // si and sj source and di and dj destination
    int si, sj, di, dj;
    cin >> si >> sj >> di >> dj;
    memset(vis, false, sizeof(vis));
    memset(level, -1, sizeof(level));
    bfs(si, sj);
    cout << level[di][dj] << endl;
    return 0;
}

    3 4
....
....
....
0 0
2 3

    n m, n rows of characters, then source row/col and destination row/col.

    Output 
    5

    Reading the output. Going from (0,0) to (2,3) in an open 3x4 grid prints 5 (2 down + 3 right).

    How it works, step by step
    1. Read n m and the grid characters, then si sj di dj.
    2. Queue holds pair<int,int> cells; level[si][sj] = 0.
    3. For each popped cell try the 4 directions; if valid and not visited, push it with level + 1.
    4. Print level[di][dj].
    Watch out. This version ignores the grid characters: walls are not blocked yet (the next file adds that). Tip: on some compilers you need #include <cstring> for memset; this file relies on another header bringing it in.
    ✅ Check yourself: In an open grid, what is the BFS distance between (r1,c1) and (r2,c2)?
    |r1 - r2| + |c1 - c2| (the Manhattan distance).

#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

vector<int> adj_list[1005];
bool vis[1005];
int count = 0;

void dfs(int src){
    vis[src] = true;
    count++;

    for(int child : adj_list[src]){
        if(!vis[child]){
            dfs(child);
        }
    }
}

int main(){
    int n, e;
    cin >> n >> e;

    while(e--){
        int a, b;
        cin >> a >> b;
        adj_list[a].push_back(b);
        adj_list[b].push_back(a);
    }

    int start_node;
    cin >> start_node;

    memset(vis, false, sizeof(vis));

    int count = 0;
    dfs(start_node);

    cout << count << endl;

    return 0;
}

    /*

https://leetcode.com/problems/flood-fill/description/

733. Flood Fill

You are given an image represented by an m x n grid of integers image, where image[i][j] represents 
the pixel value of the image. You are also given three integers sr, sc, and color. Your task is to 
perform a flood fill on the image starting from the pixel image[sr][sc].

To perform a flood fill:

1. Begin with the starting pixel and change its color to color.
2. Perform the same process for each pixel that is directly adjacent (pixels that share a side with the 
original pixel, either horizontally or vertically) and shares the same color as the starting pixel.
3. Keep repeating this process by checking neighboring pixels of the updated pixels and modifying their 
color if it matches the original color of the starting pixel.
4. The process stops when there are no more adjacent pixels of the original color to update.
Return the modified image after performing the flood fill.

 

Example 1:

Input: image = [[1,1,1],[1,1,0],[1,0,1]], sr = 1, sc = 1, color = 2

Output: [[2,2,2],[2,2,0],[2,0,1]]

From the center of the image with position (sr, sc) = (1, 1) (i.e., the red pixel), all pixels 
connected by a path of the same color as the starting pixel (i.e., the blue pixels) are colored with 
the new color.

Note the bottom corner is not colored 2, because it is not horizontally or vertically connected to 
the starting pixel.

Example 2:

Input: image = [[0,0,0],[0,0,0]], sr = 0, sc = 0, color = 0

Output: [[0,0,0],[0,0,0]]

Explanation:

The starting pixel is already colored with 0, which is the same as the target color. Therefore, no 
changes are made to the image.

Constraints:

m == image.length
n == image[i].length
1 <= m, n <= 50
0 <= image[i][j], color < 2^16
0 <= sr < m
0 <= sc < n

*/


class Solution {
public:
    vector<pair<int, int>> direction = {{0, 1}, {0, -1}, {-1, 0}, {1, 0}};

    bool valid(int i, int j, int n, int m){
        if(i < 0 || i >= n || j < 0 || j >= m){
            return false;
        }
        return true;
    }

    void dfs(vector<vector<int>>& image, int row, int col, int origColor, int newColor){
        image[row][col] =  newColor;

        for(int i = 0; i < 4; i++){
            int newRow = row + direction[i].first;
            int newCol = col + direction[i].second;

            if(valid(newRow, newCol, image.size(), image[0].size()) && image[newRow][newCol] == origColor){
                dfs(image, newRow, newCol, origColor, newColor);
            }
        }
    }

    vector<vector<int>> floodFill(vector<vector<int>>& image, int sr, int sc, int color) {
        if(image[sr][sc] != color){
            dfs(image, sr, sc, image[sr][sc], color);
        }
        return image;
    }
};

    How it works, step by step
    1. If the start pixel already has the new colour, return the image unchanged (this also avoids endless recursion).
    2. dfs sets the current pixel to newColor.
    3. For each of the 4 neighbours inside the image whose colour equals origColor, recurse.
    4. Repainted pixels no longer match origColor, so they act as their own visited marks.
    ✅ Check yourself: Why is no vis array needed here?
    A repainted pixel no longer has the original colour, so the colour check itself prevents revisiting (as long as new colour != old colour).

    📌 Remember

    • DFS = mark, then recurse into each unvisited neighbour.
    • Grid cell = node; 4 directions; always check valid first.
    • BFS on a grid gives the fewest steps; DFS only explores.
    • Components: loop all nodes, start DFS on unvisited, count starts.
    • Avoid global names like count that clash with std.

    ✅ Check yourself

    What three checks guard a grid neighbour before you visit it?
    Inside the grid (valid), not visited, and not a wall.
    Can DFS find the shortest path in a grid?
    Not in general; it finds *a* path. Use BFS for the shortest one.
    How would you get the largest component instead of all sizes?
    Keep mx = max(mx, component_size) after each DFS.
