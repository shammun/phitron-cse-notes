    Module 1Graph basics & the three ways to store a graphThe algorithms course opens with graphs: dots (nodes) joined by lines (edges). Before you can search a graph you must store it in memory. This module builds the three standard storages, adjacency matrix, adjacency list and edge list, and shows when each one is handy.4 programsModule 2Breadth-first search (BFS), levels and pathsBFS explores a graph layer by layer from a source using a queue. Because it reaches nodes in order of distance, the same code also gives the shortest number of edges to every node (its level) and, with a parent array, the actual shortest path. These patterns come back in almost every later graph problem.9 programsModule 3DFS, grids and connected componentsThis module adds depth-first search, which goes as deep as possible before backing up, written with recursion. It then moves both BFS and DFS onto 2D grids, where each cell is a node, and uses DFS to count connected components and their sizes.9 programsModule 4Assignment 1: graph & grid basicsThe first graded assignment. It checks that you can read a graph, look at adjacency lists directly, and run BFS on a grid to test reachability, count apartments (components) and measure their sizes. Each problem is a small twist on the Module 2-3 templates.5 programsModule 5Grid DFS/BFS on LeetCode: islandsA module of LeetCode practice built on one template: loop over every cell and start a DFS (or BFS) from each unvisited land cell. Small changes to that template count islands, measure their area or perimeter, add up values, or check a condition on the whole island with a flag.10 programsModule 6Cycle detection & weighted adjacency listsThis module asks: does a graph contain a cycle? In an undirected graph a visited neighbour that is not your parent means a cycle; in a directed graph you need to know whether the neighbour is still on the current DFS path. It also shows how to store edge weights, preparing for Dijkstra.7 programsModule 7Dijkstra's shortest pathWhen edges have weights, BFS levels are no longer shortest distances. Dijkstra's algorithm fixes this by always expanding the node with the smallest known distance, using a min-priority queue. The module builds a naive queue version first, then the optimized priority-queue version, and practises it on GFG, CSES and LeetCode.7 programsModule 8Mid-term: grid search problemsThe mid-term exam solutions. All four are grid problems: reachability with DFS, the smallest component area, knight moves with BFS on a chessboard, and printing the BFS path through a maze with a parent array. Together they are a good revision of Modules 2-6.4 programsModule 9Bellman-Ford & negative cyclesBellman-Ford finds single-source shortest paths even with negative edge weights. It simply relaxes every edge n−1 times. One more round that still improves a distance proves a negative cycle, where no shortest path exists.3 programsModule 10Floyd-Warshall: all-pairs shortest pathsThis module moves from single-source shortest paths (Dijkstra, Bellman-Ford) to all-pairs shortest paths with Floyd-Warshall. You keep one n x n matrix and let every node, one by one, act as a stop-over. The same matrix also tells you whether a negative cycle exists. The practice day repeats Bellman-Ford and Floyd-Warshall on judge problems.8 programsModule 11Disjoint Set Union (Union-Find)DSU keeps track of which items belong to the same group, and can merge two groups quickly. Each group has a leader; find walks up to the leader and union joins two leaders. With path compression and union by size both operations are almost O(1). The module uses DSU to detect cycles in undirected graphs and to count connected components.8 programsModule 12Assignment 2: shortest paths, DSU and a greedy scanThis assignment checks the graph tools from the last modules on judge-style problems. You use Bellman-Ford when edges can be negative, Floyd-Warshall when many pair queries come in, and DSU to count edges that close a cycle. The last problem is a simple one-pass scan for the two tallest lines.4 programsModule 13Graph problem solving: DSU, Dijkstra path, grid BFSA problem-solving module that applies earlier graph tools to judge problems. DSU tracks components while roads are added, and helps rebuild a road network. Dijkstra is extended to print the actual path, and BFS on a grid finds the fewest moves. The main skill is spotting which tool a story is really asking for.4 programsModule 14Recursion and the first steps of dynamic programmingThe module starts with recursion: a function that solves a problem by calling itself on a smaller version. Plain recursive Fibonacci repeats the same work many times. Memoization (top-down DP) and a bottom-up loop remove that repeated work. The practice problems apply the same ideas to digits, factorials, reachability and Tribonacci.11 programsModule 150-1 Knapsack and choice-based DP0-1 knapsack is the classic 'take it or leave it' DP: for each item you either put it in the bag or skip it, and you keep the better result. The state is (item index, remaining capacity), which you memoize in a 2D table. The practice day uses the same 'make a choice, keep the best' idea on grid paths, stairs, house robbing and Pascal's triangle.8 programsModule 16Final exam: DP, BFS on numbers, knapsack, anagramsThe course's final exam problems. Two ask for the same sequence in top-down and bottom-up style. One turns 'can I reach N?' into a BFS over numbers. One is a straight 0-1 knapsack with several test cases, and the last is an anagram check by sorting.5 programsModule 17Subset sum family and unbounded knapsackSubset sum asks whether some items add up to a target: the knapsack idea with 'reach exactly this sum' instead of 'maximise value'. Small changes to the same recursion count the subsets, test whether an array splits into two equal halves, or allow an item to be used many times (unbounded knapsack). The code files in this module carry a few classic bugs, which make them good for learning.6 programsModule 18Merge sort, LCS and Kruskal's MSTThree classic algorithms close the course. Merge sort shows divide and conquer: split the array in half, sort each half, merge them. Longest common subsequence is a two-string DP. Kruskal's algorithm builds a minimum spanning tree by taking the cheapest edges that do not form a cycle, using DSU. The module's quiz material also contrasts substrings with subsequences.7 programsMock ContestMock contest: search, sets, number reasoning, greedy, partition DPA practice contest before the final. The first three problems need simple tools: a linear search, a set for unique sorted letters, and a little number reasoning. The last two files hold only the problem statements, so the notes explain how to attack them: a sort-then-greedy idea and a subset DP with a size limit.7 programsFinal ContestFinal contest: prefix sums, decoding, counting subsequencesThe course's final contest. The problems reward quick pattern spotting: prefix sums for range queries, a two-step string walk for decoding, a counting argument for the missing pair, a closed formula for a repeating sequence, a frequency structure for 'most common value' queries, and a small DP that counts subsequences. Two files hold only the statement, so their notes describe the approach.8 programs
