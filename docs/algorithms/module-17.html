    Subset sum family and unbounded knapsack

    Subset sum asks whether some items add up to a target: the knapsack idea with 'reach exactly this sum' instead of 'maximise value'. Small changes to the same recursion count the subsets, test whether an array splits into two equal halves, or allow an item to be used many times (unbounded knapsack). The code files in this module carry a few classic bugs, which make them good for learning.

    💡 Key ideas

    Subset sum state

    subset_sum(i, sum) = can items 0..i pick a subset adding to exactly sum? When no items are left, the answer is yes only if sum == 0.

    if (i < 0) return sum == 0;

    Take or skip, combined with OR

    If val[i] <= sum, the answer is 'take it and reach sum - val[i]' or 'skip it and reach sum'.

    return subset_sum(i-1, sum - val[i]) || subset_sum(i-1, sum);

    Counting instead of yes/no

    Replace OR with + and return 1/0 at the base case: the result is the number of subsets with that sum.

    Equal partition

    An array splits into two equal-sum parts only if the total is even and some subset reaches total/2.

    Unbounded knapsack

    When items can be reused, taking item i keeps you at index i instead of moving to i-1.

    op1 = knapsack(i, w - weight[i]) + val[i];

    Shadowing a global array

    A local int val[n] in main hides the global val that the recursive function reads. The input goes into the local copy and the function only sees zeros.

    Memo range must cover the call

    Initialise dp for every sum the recursion can ask about (0..target inclusive); otherwise the default 0 looks like a stored answer.

    #include <iostream>
#include <vector>
#include <algorithm>    
#include <string>

using namespace std;
int val[1005];

bool subset_sum(int i, int sum){ // O(2^n)
    if(i<0){
        if(sum == 0){
            return true;
        } else{
            return false;
        }
    }
    if(val[i] <= sum){
        bool op1 = subset_sum(i-1, sum-val[i]);
        bool op2 = subset_sum(i-1, sum);
        return op1 || op2;
    }
    else{
        return subset_sum(i-1, sum);
    }
}

int main(){
    int n;

    cin >> n;
    int val[n];
    for(int i=0; i<n; i++){
        cin >> val[i];
    }

    int sum;
    cin >> sum;
    if(subset_sum(n-1, sum)){
        cout << "YES\n" << endl;
    } else{
        cout << "NO\n" << endl;
    }

    return 0;
}
    Input (stdin)
    4
1 2 3 4
5

    n, the n values, then the target. {1,4} and {2,3} both make 5, so YES is expected.

    Output 
    NO

    Reading the output. Prints NO (plus a blank line), which is wrong: see Watch out.

    How it works, step by step
    1. Read n, the values, and the target sum.
    2. Base case i < 0: true only when sum == 0.
    3. If val[i] <= sum, return take OR skip.
    4. Otherwise only skip.
    5. Print YES or NO.
    Watch out. main declares its own int val[n], which shadows the global val used by subset_sum. The function sees only zeros, so it answers YES only for target 0. Fix: delete int val[n]; in main. Also, "YES\n" << endl prints an extra blank line; use one of them.
    ✅ Check yourself: After the fix, what does the program print for values 2 4 6 and target 5?
    NO: all values are even, so no subset can sum to an odd number.

    #include <iostream>
#include <vector>
#include <algorithm>    
#include <string>

using namespace std;
int val[1005];
int dp[1005][1005]; 

bool subset_sum(int i, int sum){ // O(N * sum)
    if(i<0){
        if(sum == 0){
            return true;
        } else{
            return false;
        }
    }
    if(dp[i][sum] != -1){
        return dp[i][sum];
    }
    if(val[i] <= sum){
        bool op1 = subset_sum(i-1, sum-val[i]);
        bool op2 = subset_sum(i-1, sum);
        dp[i][sum] = op1 || op2;
        return dp[i][sum];
    }
    else{
        dp[i][sum] = subset_sum(i-1, sum);
        return dp[i][sum];
    }
}

int main(){
    int n;

    cin >> n;
    int val[n];
    for(int i=0; i<n; i++){
        cin >> val[i];
    }

    int sum;
    cin >> sum;

    for(int i=0; i<=n; i++){
        for(int j=0; j<=sum; j++){
            dp[i][j] = -1;
        }
    }

    if(subset_sum(n-1, sum)){
        cout << "YES\n" << endl;
    } else{
        cout << "NO\n" << endl;
    }

    return 0;
}
    Input (stdin)
    4
1 2 3 4
5

    Same input as the plain version (YES expected).

    Output 
    NO

    Reading the output. Prints NO (and a blank line), which is wrong for the same shadowing reason.

    How it works, step by step
    1. Fill dp[i][j] = -1 for i up to n and j up to sum inclusive.
    2. Return the stored value if dp[i][sum] != -1.
    3. Otherwise compute take OR skip, store it, and return it.
    4. Print YES or NO.
    Watch out. Remove the local int val[n]; in main so the input fills the global array. After that it prints YES.
    ✅ Check yourself: Why can a bool result be stored in an int table with -1 as 'unknown'?
    true and false are stored as 1 and 0, so -1 is free to mean 'not computed yet'.

    #include <iostream>
#include <vector>
#include <algorithm>    
#include <string>

using namespace std;
int val[1005];
int dp[1005][1005]; 

int subset_sum(int i, int sum){ // O(N * sum)
    if(i<0){
        if(sum == 0){
            return 1;
        } else{
            return 0;
        }
    }
    if(dp[i][sum] != -1){
        return dp[i][sum];
    }
    if(val[i] <= sum){
        int op1 = subset_sum(i-1, sum-val[i]);
        int op2 = subset_sum(i-1, sum);
        dp[i][sum] = op1 + op2;
        return dp[i][sum];
    }
    else{
        dp[i][sum] = subset_sum(i-1, sum);
        return dp[i][sum];
    }
}

int main(){
    int n;

    cin >> n;
    int val[n];
    for(int i=0; i<n; i++){
        cin >> val[i];
    }

    int sum;
    cin >> sum;

    for(int i=0; i<=n; i++){
        for(int j=0; j<=sum; j++){
            dp[i][j] = -1;
        }
    }

    cout << subset_sum(n-1, sum) << endl; // n-1 as we are starting from the last index and
    // n is the size of the array

    return 0;
}

    1. Base case i < 0: return 1 if sum == 0, else 0.

int val[1005];
int dp[1005][1005];

bool subset_sum(int i, int sum){
    if(i < 0){
        if(sum == 0){
            return true;
        } else{
            return false;
        }
    }

    if(dp[i][sum] != -1){
        return dp[i][sum];
    }

    if(val[i] <= sum){
        bool op1 = subset_sum(i-1, sum-val[i]);
        bool op2 = subset_sum(i-1, sum);
        dp[i][sum] = op1 || op2;
        return dp[i][sum];
    }
    else{
        dp[i][sum] = subset_sum(i-1, sum);
        return dp[i][sum];
    }
}

int main(){
    int n;
    cin >> n;
    int sum = 0;
    int val[n];

    for(int i = 0; i < n; i++){
        cin >> val[i];
        sum += val[i];
    }


    if(sum %2 != 0){
        cout << "NO\n";
        return 0;
    } else{

        int half = sum / 2;

        for(int i = 0; i < n; i++){
            for(int j = 0; j <= half; j++){
                dp[i][j] = -1;
            }
        }

        if(subset_sum(n-1, sum)){
            cout << "YES\n";
        } else{
            cout << "NO\n";
        }
    }
}
    Input (stdin)
    4
1 5 11 5

    n, then the values. {1, 5, 5} and {11} both sum to 11, so YES is expected.

    Output 
    NO

    Reading the output. Prints NO, which is wrong: see Watch out.

    How it works, step by step
    1. Read the values and add them into sum.
    2. Odd sum: print NO.
    3. Even: half = sum / 2, reset dp for sums 0..half.
    4. Ask subset_sum whether the target can be reached and print YES or NO.
    Watch out. Two bugs. (1) subset_sum(n-1, sum) should be subset_sum(n-1, half): the target is half the total, and dp[i][sum] was never set to -1, so the call returns 0 at once. (2) The local int val[n] shadows the global array the function reads, so the function only sees zeros. Fix both (delete the local array, pass half) and it prints YES.
    ✅ Check yourself: Values 3 1 1 2 2 1: can they be split into two equal halves?
    Yes. The total is 10, and {3, 2} reaches 5, leaving {1, 1, 2, 1} = 5.

    #include <iostream>
#include <vector>
#include <algorithm>
#include <string>

using namespace std;

int val[1005], weight[1005];
int dp[1005][1005];

int knapsack(int i, int max_weight){
    if(i < 0 || max_weight <= 0){
        return 0;
    }

    if(dp[i][max_weight] != -1){
        return dp[i][max_weight];
    }

    if(weight[i] <= max_weight){ // when we still have space in the bag, we can either take 
        // the current item or not
        int op1 = knapsack(i, max_weight - weight[i]) + val[i]; // taking the current item
        int op2 = knapsack(i-1, max_weight); // not taking the current item
        dp[i][max_weight] = max(op1, op2);
        return dp[i][max_weight];
    } else{
        dp[i][max_weight] = knapsack(i-1, max_weight);
        return dp[i][max_weight];
    }
}

int main(){
    int n, max_weight;

    cin >> n;
    
    for(int i=0; i<n; i++){
        cin >> val[i];
    }
    for(int i=0; i<n; i++){
        cin >> weight[i];
    }
    cin >> max_weight;

    for(int i=0; i<n; i++){
        for(int j=0; j<max_weight; j++){
            dp[i][j] = -1;
        }
    }

    cout << knapsack(n-1, max_weight) << endl;

    return 0;
}
    Input (stdin)
    2
10 15
2 3
7

    n, values, weights, capacity. Best is 2 + 2 + 3 = 7 for 10 + 10 + 15 = 35.

    Output 
    0

    Reading the output. Prints 0, which is wrong: see Watch out.

    How it works, step by step
    1. Read n, values, weights, capacity.
    2. Reset dp to -1.
    3. If item i fits: take it and stay at i, or skip it and move to i-1; keep the max.
    4. If it does not fit, only skip.
    5. Print knapsack(n-1, max_weight).
    Watch out. Same init bug as Module 15: j < max_weight leaves dp[i][max_weight] at 0, so the first call returns 0 immediately. Use j <= max_weight; then the program prints 35.
    ✅ Check yourself: Which one-token change turns 0-1 knapsack into unbounded knapsack?
    In the take branch, call knapsack(i, ...) instead of knapsack(i-1, ...).

    📌 Remember

    • Subset sum = knapsack with 'reach exactly' and OR instead of max.
    • Counting subsets: same recursion, add the two options, base case returns 1 or 0.
    • Equal partition = even total + subset sum to half.
    • Unbounded: stay on the same item after taking it.
    • Never re-declare a global array inside main, and initialise dp up to the target inclusive.

    ✅ Check yourself

    Coin Change II counts ways to make an amount with unlimited coins. Which two ideas from this module does it combine?
    Counting (add the options) and unbounded use (stay on the same coin after taking it).
    Total = 15. Can the array be split into two equal-sum parts?
    No, an odd total can never be split into two equal integer sums.
    Why must the base case check sum == 0 rather than just return true?
    Running out of items only means success if the chosen items added up exactly; any leftover sum means this path failed.
