    Introduction to Algorithms · Module 10

    Floyd-Warshall: all-pairs shortest paths

    This module moves from single-source shortest paths (Dijkstra, Bellman-Ford) to all-pairs shortest paths with Floyd-Warshall. You keep one n x n matrix and let every node, one by one, act as a stop-over. The same matrix also tells you whether a negative cycle exists. The practice day repeats Bellman-Ford and Floyd-Warshall on judge problems.

    🧭 Start here

    Old road atlases print a distance chart: the towns listed down the side, the same towns across the top, and in every square the distance between that pair of towns. Module 7 and Module 9 gave you tools for one row of such a chart. Dijkstra or Bellman-Ford, started at one town, fills in the distances from that town to all the others. This module fills in the whole chart.

    Take four cities and five one-way roads:

    1 --5--> 2     2 --3--> 3     3 --1--> 4
1 --10-> 3     2 --9--> 4

    The plodding way to get the whole chart is to run a single-source algorithm once per city: start at 1, then at 2, then at 3, then at 4. It does work. But Dijkstra refuses negative road costs, and Bellman-Ford four times over is slow.

    Floyd-Warshall never walks the graph at all. It works on the chart itself. Write the map down as a table: 0 on the diagonal, the road cost where a direct road exists, and a dash where you know of no way yet.

            to 1   2   3   4
from 1     0   5  10   -
     2     -   0   3   9
     3     -   -   0   1
     4     -   -   -   0

    Now the single idea of the module. Point at one city and ask the table one question: if travellers were allowed to stop over in this city, would anything get cheaper? Try city 2. For every pair (i, j), compare the square you already have with the cost of going i -> 2 -> j.

    Two squares improve. 1 to 3 was 10 by the direct road, but 1 -> 2 -> 3 costs 5 + 3 = 8, so write 8. 1 to 4 was a dash, and 1 -> 2 -> 4 costs 5 + 9 = 14, so write 14. Nothing else changes, because no road leads into city 2 from 3 or 4.

    after letting city 2 be a stop-over

        to 1   2   3   4
from 1     0   5   8*  14*
     2     -   0   3   9
     3     -   -   0   1
     4     -   -   -   0

* changed this round

    Then you do the same for city 3, and for city 4, and (first of all, in code) for city 1. Letting city 3 be a stop turns 1 to 4 into 8 + 1 = 9 and 2 to 4 into 3 + 1 = 4. Note that each round starts from the improved table of the round before, which is why a route may end up using several stops although each round adds only one.

    That is the whole algorithm: three nested loops, and the outer one is the city being allowed as a stop.

    Say plainly what is new. Until now a shortest-path algorithm grew outwards from one source, with a queue or a priority queue and a visited array. Here nothing is visited and nothing is queued. You hold the answers for every pair at once, and each round widens the set of cities that may be used as stop-overs. The outer loop must be k; move it inwards and the answers are quietly wrong.

    for(int k = 0; k < n; k++)      // k = the allowed stop-over
  for(int i = 0; i < n; i++)
    for(int j = 0; j < n; j++)
      if(d[i][k] != INF && d[k][j] != INF &&
         d[i][k] + d[k][j] < d[i][j])
          d[i][j] = d[i][k] + d[k][j];

    One thing to watch. A dash is stored as a huge number such as INT_MAX, and a huge number plus a road cost overflows and comes out negative, which would look like a marvellous shortcut. So check both halves before you add them, exactly as in the snippet above.

    Why use it? The cost is n x n x n steps. With n = 100 that is 1,000,000 steps, done in a blink, and afterwards every question "cheapest cost from X to Y?" is one look at one square, so 100,000 queries cost almost nothing. With 100,000 cities, n^3 is hopeless and Dijkstra from the single source you care about is the right tool. Negative road costs are allowed here, unlike Dijkstra. And the diagonal reports trouble by itself: if any d[i][i] falls below 0, city i sits on a cycle you can go round and round to lose cost for ever, so shortest paths do not exist.

    The programs below run this on a plain directed graph, use the diagonal to detect a negative cycle, and answer many pair queries on an undirected map after one fill of the table.

    💡 Key ideas

    Adjacency matrix as a distance table

    adj_mat[i][j] holds the best known cost from i to j. Start with 0 on the diagonal, the edge weight where an edge exists, and infinity everywhere else.

    adj_mat[i][j] = (i == j) ? 0 : INT_MAX;

    Relax through a middle node k

    For each pair (i, j) ask: is going i -> k -> j cheaper than what I have? If yes, overwrite. The outer loop must be k, so that after round k every path may use nodes 0..k as stop-overs.

    for k: for i: for j:
  if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];

    Guard against infinity

    INT_MAX + something overflows and becomes a huge negative number. Always check that both halves are not infinity before adding.

    if (d[i][k] != INT_MAX && d[k][j] != INT_MAX && ...)

    Negative cycle check

    After the three loops, if any d[i][i] is below 0, node i sits on a cycle whose total weight is negative, so shortest paths are not defined.

    Bellman-Ford recap

    Relax every edge V-1 times. One extra pass that still improves something means a negative cycle is reachable from the source.

    Choosing the algorithm

    Dijkstra: one source, no negative edges, O(E log V). Bellman-Ford: one source, negative edges allowed, O(V·E). Floyd-Warshall: every pair, small n (about n <= 500), O(n^3).

    City 0 may now be a stop-over. Only city 3 has a road into city 0, so only row 3 can improve: 3 -> 0 -> 1 costs 6 + 3 = 9 and 3 -> 0 -> 2 costs 6 + 7 = 13. Two dashes become numbers.

    k = 1: cities 0 and 1 may be stop-overs

        to  0   1   2   3
from 0      0   3   4*  -
     1      -   0   1   -
     2      -   -   0   2
     3      6   9  10*  0

    City 1 joins in. 0 -> 1 -> 2 costs 3 + 1 = 4, cheaper than the direct road of 7, so the 7 is overwritten. And 3 -> 1 -> 2 costs 9 + 1 = 10, better than the 13 written a moment ago.

    k = 2: cities 0, 1 and 2 may be stop-overs

        to  0   1   2   3
from 0      0   3   4   6*
     1      -   0   1   3*
     2      -   -   0   2
     3      6   9  10   0

    City 2 joins in, and this is where several stops stack up: 0 -> 2 already means 0 -> 1 -> 2, so 0 -> 2 -> 3 = 4 + 2 = 6 is really a three-road route. Each round builds on the last one.

    k = 3: every city may be a stop-over

        to  0   1   2   3
from 0      0   3   4   6
     1      9*  0   1   3
     2      8* 11*  0   2
     3      6   9  10   0

    City 3 is the last stop-over, and it is the only way back to city 0 (road 3 -> 0 costs 6). Three more dashes fill in: 1 -> 3 -> 0 = 9, 2 -> 3 -> 0 = 8, 2 -> 3 -> 0 -> 1 = 11.

    done: every pair answered

        to  0   1   2   3
from 0      0   3   4   6
     1      9   0   1   3
     2      8  11   0   2
     3      6   9  10   0

    No dashes left, and this is exactly what the program prints. Row 0 reads 0 3 4 6, and row 1 starts at 9 because 1 -> 2 -> 3 -> 0 costs 1 + 2 + 6. Any "cheapest cost from X to Y?" is now one look at one square. The diagonal is all 0, so there is no negative cycle.

    // Floyd-Warshall: the cheapest route between EVERY pair of nodes, all at once.
//
// Dijkstra (Module 7) and Bellman-Ford (Module 9) each fill in one ROW of the
// distance chart: you pick a starting node and learn the cost to all the others.
// Here we want the whole chart, so we keep the chart itself as an n x n matrix
// and keep improving it in place.
//
// adj_mat[i][j] always means "the cheapest cost from i to j that I know of so
// far". It starts out as the direct road only. Each round of the outer loop lets
// one more node be used as a stop-over in the middle, so after the last round
// every pair has been allowed to go through every node and the chart is final.
//
// Time O(n^3) - three nested loops, each n long. Space O(n^2) for the matrix.

#include <iostream>
#include <queue>    // not used here; carried over from the earlier graph files
#include <cstring>  // same - Dijkstra/BFS needed these, Floyd-Warshall does not
#include <vector>

using namespace std;

int main(){
    int n, e;        // n = number of nodes, e = number of directed edges
    cin >> n >> e;

    // The chart: one row and one column per node. Note this is a variable length
    // array - its size is only known while the program runs. g++ allows that,
    // standard C++ does not, so for a big n a fixed-size global array is safer.
    int adj_mat[n][n];

    // The starting chart. Staying where you are costs nothing, so the diagonal is
    // 0. Every other pair is "no route known yet", written as INT_MAX, the biggest
    // int there is. INT_MAX really lives in <climits>, which this file never
    // includes; it only compiles because one of the headers above drags <climits>
    // in. Adding #include <climits> would make that safe instead of lucky.
    for(int i=0; i<n; i++){
        for(int j=0; j<n; j++){
            if(i == j){
                adj_mat[i][j] = 0;
            } else{
                adj_mat[i][j] = INT_MAX;
            }
        }
    }

    // e lines of "a b c": a road from a to b costing c. Only [a][b] is written,
    // because the graph is directed. The commented line below is what an
    // undirected graph would need. Plain assignment means a second road between
    // the same pair overwrites the first, even if the first was cheaper; when
    // that can happen, use min() instead (see shortest_route_2.cpp).
    while(e--){
        int a, b, c;
        cin >> a >> b >> c;
        adj_mat[a][b] = c;
        // adj_mat[b][a] = c; // for undirected graph
    }

    // The heart of the algorithm.
    //
    // k is the stop-over node and it MUST be the outermost loop. After round k
    // has finished, every pair i,j holds the best route that uses only nodes
    // 0..k in the middle. If k sat inside, a pair could be settled before the
    // stop-over node it actually needs had had its turn.
    //
    // i is where we start, j is where we want to end up: "is going i -> k -> j
    // cheaper than the best i -> j I have?"
    for(int k=0; k<n; k++){
        for(int i=0; i<n; i++){
            for(int j=0; j<n; j++){
                // The commented one-liner reads better but is a trap: an unknown
                // leg costs INT_MAX, and INT_MAX + anything positive overflows
                // into a negative number, which then looks like a bargain. So both
                // legs are checked for INT_MAX before they are added together.
                // adj_mat[i][j] = min(adj_mat[i][j], adj_mat[i][k] + adj_mat[k][j]);
                if(adj_mat[i][k] != INT_MAX && adj_mat[k][j] != INT_MAX && adj_mat[i][k] + adj_mat[k][j] < adj_mat[i][j]){
                    adj_mat[i][j] = adj_mat[i][k] + adj_mat[k][j];
                }
            }
        }
    }

    // Print the finished chart. Row i, column j is the answer for i -> j. A cell
    // still holding INT_MAX was never improved, so there is no route at all from
    // i to j - print INF rather than a meaningless huge number.
    for(int i=0; i<n; i++){
        for(int j=0; j<n; j++){
            if(adj_mat[i][j] == INT_MAX){
                cout << "INF ";
            } else{
                cout << adj_mat[i][j] << " ";
            }
        }
        cout << endl;
    }

    return 0;
}

    4 5
0 1 3
1 2 1
0 2 7
2 3 2
3 0 6

    n e, then e lines from to weight. Nodes are 0-based.

    Reading the output. Row i, column j is the cheapest cost from i to j. Row 0 is 0 3 4 6: the direct edge 0->2 costs 7, but 0->1->2 costs 3+1 = 4, so the table keeps 4. Row 1 starts with 9 because 1->2->3->0 = 1+2+6.

    How it works, step by step
    1. Read n nodes and e edges; build adj_mat[n][n] with 0 on the diagonal and INT_MAX elsewhere.
    2. For each edge a b c store adj_mat[a][b] = c (only one direction, the graph is directed).
    3. Outer loop k picks the stop-over node; inner loops i, j try every pair.
    4. If both adj_mat[i][k] and adj_mat[k][j] are finite and their sum is smaller, update adj_mat[i][j].
    5. Print the matrix row by row, writing INF for INT_MAX.
    Watch out. INT_MAX comes from <climits>; the file does not include it and only compiles because this compiler pulls it in through another header. Add #include <climits> to be safe.
    ✅ Check yourself: Why must k be the outermost loop?
    Because after finishing round k, every pair already knows the best path that uses only nodes 0..k in the middle. If k were inside, a pair could be finalised before the stop-over nodes it needs were processed.

    // Floyd-Warshall again, this time asked a different question: does the graph
// contain a negative cycle - a loop you can walk round for ever, getting cheaper
// each time? Bellman-Ford answered this in Module 9 by doing one extra relaxation
// round. The matrix answers it even more cheaply, in one glance at the diagonal.
//
// Everything down to the triple loop is exactly floyd-warshall.cpp; read the
// comments there for why k is outermost and why INT_MAX is checked before adding.
// The new part is at the bottom.

#include <iostream>
#include <queue>
#include <cstring>
#include <vector>

using namespace std;

int main(){
    int n, e;
    cin >> n >> e;
    int adj_mat[n][n];

    for(int i=0; i<n; i++){
        for(int j=0; j<n; j++){
            if(i == j){
                adj_mat[i][j] = 0;
            } else{
                adj_mat[i][j] = INT_MAX;
            }
        }
    }

    while(e--){
        int a, b, c;
        cin >> a >> b >> c;
        adj_mat[a][b] = c;
        // adj_mat[b][a] = c; // for undirected graph
    }

    for(int k=0; k<n; k++){
        for(int i=0; i<n; i++){
            for(int j=0; j<n; j++){
                // adj_mat[i][j] = min(adj_mat[i][j], adj_mat[i][k] + adj_mat[k][j]);
                if(adj_mat[i][k] != INT_MAX && adj_mat[k][j] != INT_MAX && adj_mat[i][k] + adj_mat[k][j] < adj_mat[i][j]){
                    adj_mat[i][j] = adj_mat[i][k] + adj_mat[k][j];
                }
            }
        }
    }

    // checking for negative cycle
    //
    // adj_mat[i][i] started at 0: standing still costs nothing. The triple loop
    // only ever lowers a cell, and the only way to lower [i][i] is to find a real
    // route that leaves i and comes back to i for a total below zero. That route
    // is a negative cycle. So one negative number anywhere on the diagonal is the
    // whole test - we do not have to hunt for the cycle itself.
    //
    // A cycle that costs exactly 0 does NOT count: the diagonal stays at 0, not
    // below it, and walking such a loop never makes anything cheaper.
    bool cycle = false;
    
    for(int i=0; i<n; i++){
        if(adj_mat[i][i] < 0){
            cycle = true;
        }
    }

    // If a negative cycle exists the numbers in the table are meaningless - every
    // pair that can reach the cycle has no "shortest" distance at all, because the
    // cost can always be driven lower. So we say so instead of printing the chart.
    if(cycle){
        cout << "Negative weighted cycle detected" << endl;
    } else{
        for(int i=0; i<n; i++){
            for(int j=0; j<n; j++){
                if(adj_mat[i][j] == INT_MAX){
                    cout << "INF ";
                } else{
                    cout << adj_mat[i][j] << " ";
                }
            }
            cout << endl;
        }
    }


    return 0;
}
    Input (stdin)
    3 3
0 1 2
1 2 -3
2 0 -1

    The cycle 0->1->2->0 costs 2 + (-3) + (-1) = -2.

    Output 
    Negative weighted cycle detected

    Reading the output. The program prints Negative weighted cycle detected because going round the cycle makes adj_mat[0][0] negative. Remove the edge 2 0 -1 and you get a normal table instead.

    How it works, step by step
    1. Build the matrix and run Floyd-Warshall exactly as in floyd-warshall.cpp.
    2. Set cycle = false, then look at every adj_mat[i][i].
    3. The diagonal starts at 0. It can only drop below 0 if some path leaves i and comes back with a total cost below zero.
    4. If cycle is true print the warning, otherwise print the matrix.
    ✅ Check yourself: Graph 0->1 (4), 1->0 (-4). Is there a negative cycle?
    No. The cycle costs 4 + (-4) = 0, so the diagonal stays 0, not below 0.

    /*

https://www.geeksforgeeks.org/problems/distance-from-the-source-bellman-ford-algorithm/1

Bellman-Ford

Given a weighted and directed graph of v vertices and edges, Find the shortest distance of all the vertex's from the source 
vertex, src and return a list of integers where the ith integer denotes the distance of the ith node from the source node. If a 
vertices can't be reach from the s then mark the distance as 10^8.
Note: If there exist a path to a negative weighted cycle from the source node then return {-1}.

Examples:

Input: edges = [[0,1,9]], src = 0

Output: [0, 9]
Explanation: Shortest distance of all nodes from source is printed

Input: edges = [[0,1,5], [1,0,3], [1,2,-1], [2,0,1]], src = 2
Output: [1, 6, 0]
Explanation: For nodes 2 to 0, we can follow the path: 2-0. This has a distance of 1. For nodes 2 to 1, we cam follow the path: 
2-0-1, which has a distance of 1+5 = 6,

Constraints:
1 ≤ V ≤ 500
1 ≤ E ≤ V*(V-1)
-1000 ≤ data of nodes, weight ≤ 1000
0 ≤ S < V

*/

#include <iostream>
#include <queue>
#include <cstring>
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
    public:
      /*  Function to implement Bellman Ford
       *   edges: vector of vectors which represents the graph
       *   src: source vertex
       *   V: number of vertices
       */
      vector<int> bellmanFord(int V, vector<vector<int>>& edges, int src) {
          // Code here
          vector<int> dist(V, 100000000);
          dist[src] = 0;
          
          for(int i=0; i< V-1; i++){
              for(auto edge : edges){
                  int u = edge[0];
                  int v = edge[1];
                  int w = edge[2];
                  if(dist[u] != 100000000 && dist[u] + w < dist[v]){
                      dist[v] = dist[u] + w;
                  }
              }
          }
          
          for(auto edge : edges){
              int u = edge[0];
              int v = edge[1];
              int w = edge[2];
              if(dist[u] != 100000000 && dist[u] + w < dist[v]){
                  return {-1};
              }
          }
          return dist;
      }
  };

    Reading the output. Prints dist = 1 6 0, matching the judge's expected [1, 6, 0]: from 2 the edge to 0 costs 1, and 2->0->1 costs 1+5 = 6. If a negative cycle were reachable you would see dist = -1.

    How it works, step by step
    1. Create dist(V, 100000000) (the judge's 'infinity') and set dist[src] = 0.
    2. Repeat V-1 times: for every edge u v w, if dist[u] is finite and dist[u] + w < dist[v], update dist[v].
    3. Why V-1? A shortest path without cycles has at most V-1 edges, and each pass fixes at least one more edge of it.
    4. Do one more pass over all edges. If anything still improves, return {-1}.
    5. Otherwise return dist.
    Watch out. The file only holds the judge's Solution class; the page adds a small test driver to run it.
    ✅ Check yourself: Why check dist[u] != 100000000 before relaxing?
    An unreachable u has no real distance. Adding a negative w to the 'infinity' value would wrongly make v look reachable.

#include <cstring>

    // from 1. LLONG_MAX is the long long version of INT_MAX and means "no route
    // known yet"; like INT_MAX it comes from <climits>, which is not included and
    // only arrives by accident through another header.
    for(int i=1; i<=n; i++){
        for(int j=1; j<=n; j++){
            if(i == j){
                adj_mat[i][j] = 0;
            } else{
                adj_mat[i][j] = LLONG_MAX;
            }

    }

    // several roads between the same two cities: a later, dearer road must not
    // wipe out a cheaper one already read.
    // Both directions are filled because the roads are two-way.
    // Note the second line reads adj_mat[a][b], not adj_mat[b][a]. It still gives
    // the right answer, but only because the line above has just set [a][b] to the
    // cheapest value and the two cells are always kept equal. Writing
    // min(adj_mat[b][a], c) would say what is meant.
    while(e--){

        cin >> a >> b >> c;
        adj_mat[a][b] = min(adj_mat[a][b], c);
        adj_mat[b][a] = min(adj_mat[a][b], c); // we have undirected graph here
    }

    /*

Shortest Routes II   (CSES 1672)

There are n cities and m roads between them. Every road joins two cities, can
be driven in both directions, and has a length. Two cities may be joined by
more than one road, and a road may even start and end in the same city. Then
q questions follow: for two cities, how long is the shortest route between
them? If there is no route at all, the answer is -1.

The questions come one after another and there can be many of them, so we do
not run a shortest-path search per question. Floyd-Warshall fills one table
with the shortest distance between every pair of cities, and after that each
question is a single lookup.

Input
The first line has three numbers n, m and q: cities, roads and questions.
The cities are numbered 1, 2, ..., n.
The next m lines each have three numbers a, b and c: a road of length c
between cities a and b.
The last q lines each have two numbers s and d: the two cities of a question.
n is small enough for an n x n table and for the n^3 triple loop (a few
hundred), while m and q can be much larger.

Output
For every question, print one line: the length of the shortest route, or -1 if
the cities are not connected.

Example

input
4 3 3
1 2 5
2 3 2
1 3 10
1 3
3 1
1 4

output
7
7
-1

Going 1 -> 2 -> 3 costs 5 + 2 = 7, which beats the direct road of length 10.
The roads are two-way, so 3 -> 1 costs the same. City 4 has no road at all, so
the third answer is -1.

*/

#include <bits/stdc++.h>
using namespace std;

/* A road can be long and a route can use many of them, so distances are
   long long. INF is 1e18/4 and not LLONG_MAX on purpose: inside the triple
   loop we add two table entries together, and INF + INF must still fit in a
   long long instead of overflowing into a negative number. Two of these still
   add up to 5e17, far below the long long limit. */
const long long INF = 1e18 / 4;

int main() {
    int n, m, q;
    cin >> n >> m >> q;

    /* (n+1) x (n+1) so that the cities can keep their own numbers 1..n and
       row 0 / column 0 simply stay unused. */
    vector<vector<long long>> dist(n + 1, vector<long long>(n + 1, INF));
    for(int i = 1; i <= n; i++) {
        dist[i][i] = 0;   // staying where you are costs nothing
    }

    while(m--) {
        int a, b;
        long long c;
        cin >> a >> b >> c;
        /* min, not plain assignment: there can be several roads between the
           same two cities, and a later expensive road must not wipe out a
           cheaper one that was read before it. */
        dist[a][b] = min(dist[a][b], c);
        dist[b][a] = min(dist[b][a], c);   // the roads are two-way
    }

    for(int k = 1; k <= n; k++) {
        for(int i = 1; i <= n; i++) {
            /* If k itself cannot be reached from i, no route through k can
               exist, so the whole inner row can be skipped. This also keeps
               INF values from being added up needlessly. */
            if(dist[i][k] == INF) continue;
            for(int j = 1; j <= n; j++) {
                if(dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                }
            }
        }
    }

    while(q--) {
        int s, d;
        cin >> s >> d;
        if(dist[s][d] == INF) {
            cout << -1 << "\n";   // '\n' instead of endl: q can be huge and
        } else {                  // endl flushes the output every time
            cout << dist[s][d] << "\n";
        }
    }

    return 0;
}

Distance from the Source (Bellman-Ford)   (GeeksforGeeks)

A directed graph has V vertices, numbered 0 .. V-1, and a list of edges. Each
edge is given as three numbers u, v, w: an edge from u to v of weight w. The
weights may be negative. Starting from a vertex src, report the shortest
distance to every vertex, in vertex order. A vertex that cannot be reached
from src gets the judge's "infinity" value 100000000 (10^8). If a negative
cycle can be reached from src, no shortest distance exists, and the answer is
the single value -1.

Why Bellman-Ford and not Dijkstra: Dijkstra settles a vertex for good the
moment it is taken out of the priority queue, and a negative edge can make a
settled distance wrong later. Bellman-Ford makes no such promise; it simply
relaxes every edge again and again.

Input (for this file's small test driver)
The first line has V and E: the number of vertices and the number of edges.
The next E lines each have u, v and w.
The last line has src.

Output
The word "dist =" followed by the distance of vertex 0, 1, ..., V-1, or
"dist = -1" when a reachable negative cycle makes the answer meaningless.

Example

input
3 4
0 1 5
1 0 3
1 2 -1
2 0 1
2

output
dist = 1 6 0

Vertex 2 is the source, so its distance is 0. The edge 2 -> 0 costs 1. From
there the edge 0 -> 1 costs 5, so vertex 1 sits at 1 + 5 = 6.

*/

#include <bits/stdc++.h>
using namespace std;

class Solution {
    public:
      /*  Function to implement Bellman Ford
       *   edges: vector of vectors which represents the graph
       *   src: source vertex
       *   V: number of vertices
       */
      vector<int> bellmanFord(int V, vector<vector<int>>& edges, int src) {
          const int INF = 100000000;   // the value the judge asks for

          vector<int> dist(V, INF);
          dist[src] = 0;

          /* A shortest path that does not repeat a vertex uses at most V-1
             edges, and one full pass over the edge list fixes at least one
             more edge of every such path. V-1 passes are therefore enough. */
          for(int i = 0; i < V - 1; i++) {
              for(auto edge : edges) {
                  int u = edge[0];
                  int v = edge[1];
                  int w = edge[2];
                  /* The dist[u] != INF guard matters: u may be unreachable,
                     and a negative w would otherwise turn the fake INF into a
                     smaller number and make v look reachable. */
                  if(dist[u] != INF && dist[u] + w < dist[v]) {
                      dist[v] = dist[u] + w;
                  }
              }
          }

          /* One extra pass. Nothing should improve any more. If something
             still does, the improvement can be repeated forever, which means
             a negative cycle sits on the way from src. */
          for(auto edge : edges) {
              int u = edge[0];
              int v = edge[1];
              int w = edge[2];
              if(dist[u] != INF && dist[u] + w < dist[v]) {
                  return {-1};
              }
          }

          return dist;
      }
};

int main() {
    int V, E;
    cin >> V >> E;

    vector<vector<int>> edges(E, vector<int>(3));
    for(int i = 0; i < E; i++) {
        cin >> edges[i][0] >> edges[i][1] >> edges[i][2];
    }

    int src;
    cin >> src;

    Solution ob;
    vector<int> dist = ob.bellmanFord(V, edges, src);

    cout << "dist =";
    for(int x : dist) {
        cout << " " << x;
    }
    cout << endl;

    return 0;
}

    How it works, step by step
    1. Keep the judge's Solution class exactly as it is typed into GeeksforGeeks - that is the part the reader submits.
    2. dist(V, 100000000) is the judge's 'infinity'; set dist[src] = 0.
    3. Relax every edge, V-1 times over: a shortest path that repeats no vertex has at most V-1 edges, and one full pass fixes at least one more edge of it.
    4. Guard every relaxation with dist[u] != INF, so a negative weight cannot shrink the fake infinity and make an unreachable vertex look reachable.
    5. Do one extra pass. Anything that still improves can improve forever, which means a negative cycle, so return {-1}.
    6. main reads V, E, the E edges and the source, calls the function and prints the vector.
    Watch out. Bellman-Ford, not Dijkstra, because of the negative edge 1 -> 2 of weight -1. Dijkstra fixes a vertex the moment it leaves the priority queue, and a negative edge found later would make that fixed value wrong.
    ✅ Check yourself: Why does one more pass after the V-1 passes prove a negative cycle?
    After V-1 passes every real shortest path is already found. Another improvement can only come from going round a loop that makes the total smaller, and that loop can be repeated without end.

C. Dijkstra?   (Codeforces 20C)

A country has n cities, numbered 1 .. n, joined by m two-way roads. Each road
has a positive length. Print the shortest route from city 1 to city n as the
list of cities you pass through, first 1 and last n. If city n cannot be
reached, print -1. If several routes are equally short, any of them is
accepted.

This is plain Dijkstra with one addition: besides the distance we remember,
for every city, which city we came from when its distance was last improved.
Walking those parents back from n gives the route.

Input
The first line has n and m.
The next m lines each have three numbers a, b and w: a road of length w
between cities a and b. There may be several roads between the same pair, and
a road may start and end in the same city. Both n and m can be around 10^5.

Output
The cities of a shortest route from 1 to n, in order, separated by spaces, or
-1 if there is no route.

Examples

input
5 6
1 2 2
2 5 5
2 3 4
1 4 1
4 3 3
3 5 1

output
1 4 3 5

The route 1 -> 4 -> 3 -> 5 costs 1 + 3 + 1 = 5. Going 1 -> 2 -> 5 would cost
2 + 5 = 7.

input
3 1
1 2 5

output
-1

*/

#include <bits/stdc++.h>
using namespace std;

/* The lengths are positive but there can be about 10^5 roads, so a route can
   be far longer than an int holds. Everything that stores or adds a distance
   is long long, and INF is a large value that still leaves room for one
   addition. */
const long long INF = 1e18 / 4;

int main() {
    int n, m;
    cin >> n >> m;

    /* vector<pair<int, long long>>: for each city, the list of (neighbour,
       road length) pairs. Size n+1 so the cities keep their own numbers. */
    vector<vector<pair<int, long long>>> adj_list(n + 1);

    while(m--) {
        int a, b;
        long long w;
        cin >> a >> b >> w;
        adj_list[a].push_back({b, w});
        adj_list[b].push_back({a, w});   // the roads are two-way
    }

    vector<long long> dis(n + 1, INF);
    vector<int> parent(n + 1, -1);   // -1 means "no city came before this one"

    /* The pair is (distance, city) in that order, because the priority queue
       compares the first member first, and greater<> turns the max-heap into
       a min-heap so the closest city comes out on top. */
    priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<pair<long long, int>>> pq;

    dis[1] = 0;
    pq.push({0, 1});

    while(!pq.empty()) {
        pair<long long, int> par = pq.top();
        pq.pop();
        long long par_dist = par.first;
        int par_node = par.second;

        /* An old, worse copy of this city may still be sitting in the queue
           from an earlier improvement. It is cheaper to skip it here than to
           search the queue and remove it. */
        if(par_dist > dis[par_node]) continue;

        for(auto child : adj_list[par_node]) {
            int child_node = child.first;
            long long child_dist = child.second;

            if(par_dist + child_dist < dis[child_node]) {
                dis[child_node] = par_dist + child_dist;
                parent[child_node] = par_node;   // remember how we got here
                pq.push({dis[child_node], child_node});
            }
        }
    }

    if(dis[n] == INF) {
        cout << -1 << endl;
        return 0;
    }

    /* Walk back from n; parent[1] is still -1, so the walk stops at the
       start. The cities come out reversed, so the list is turned around. */
    vector<int> path;
    int node = n;
    while(node != -1) {
        path.push_back(node);
        node = parent[node];
    }
    reverse(path.begin(), path.end());

    for(int i = 0; i < (int)path.size(); i++) {
        if(i > 0) cout << " ";
        cout << path[i];
    }
    cout << endl;

    return 0;
}
    Input (stdin)
    5 6
1 2 2
2 5 5
2 3 4
1 4 1
4 3 3
3 5 1

    n m, then m roads a b w. Cities are numbered from 1; the route always has to start at 1 and end at n.

    Output 
    1 4 3 5

    Reading the output. Prints 1 4 3 5, the route of cost 1 + 3 + 1 = 5. The other way round, 1 -> 2 -> 5, would cost 2 + 5 = 7. With the second sample from the file header (3 1 and the single road 1 2 5) it prints -1, because city 3 is on its own.

    How it works, step by step
    1. Store the graph as vector<vector<pair<int, long long>>> adj_list(n + 1): for each city a list of (neighbour, road length).
    2. Use a min-heap priority_queue<pair<long long, int>, vector<...>, greater<...>> with the distance first, because the queue compares the first member of the pair.
    3. Whenever dis[child] improves, also set parent[child] = par_node - that one line is all the path printing needs.
    4. Skip a popped pair when par_dist > dis[par_node]: it is an old, worse copy left in the queue by a later improvement.
    5. If dis[n] is still INF, print -1.
    6. Otherwise walk back from n through parent until -1 (city 1 keeps -1), reverse the list, and print it.
    Watch out. long long everywhere a distance is stored or added. The roads are short on their own, but a route can use about 10^5 of them and the total then leaves int behind. The name of the problem is a joke about people who answer it with a plain BFS.
    ✅ Check yourself: Why is the pair (distance, city) and not (city, distance)?
    A priority_queue of pairs compares the first member first. Putting the distance first is what makes the closest city come out of the heap next.

    📌 Remember

    • Floyd-Warshall = three loops, k outside, relax d[i][j] through k.
    • Initialise with 0 on the diagonal and infinity elsewhere; guard every addition against infinity.
    • A negative value on the diagonal after the loops means a negative cycle.
    • Use it when n is small and you need many pair queries: pay O(n^3) once, answer each query in O(1).
    • Keep the minimum when the input can repeat an edge.

    ✅ Check yourself

    n = 400. Is Floyd-Warshall fast enough?
    400^3 = 64 million simple steps, which is fine within about a second.
    When would you pick Bellman-Ford over Floyd-Warshall?
    When you only need distances from one source (or n is too big for n^3) and edges can be negative.
    Why use long long for distances in Shortest Routes II?
    A path can use up to n-1 roads each costing up to 10^9, so the total can exceed the int limit.
