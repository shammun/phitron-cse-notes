    Floyd-Warshall: all-pairs shortest paths

    This module moves from single-source shortest paths (Dijkstra, Bellman-Ford) to all-pairs shortest paths with Floyd-Warshall. You keep one n x n matrix and let every node, one by one, act as a stop-over. The same matrix also tells you whether a negative cycle exists. The practice day repeats Bellman-Ford and Floyd-Warshall on judge problems.

    💡 Key ideas

    Adjacency matrix as a distance table

    adj_mat[i][j] holds the best known cost from i to j. Start with 0 on the diagonal, the edge weight where an edge exists, and infinity everywhere else.

    adj_mat[i][j] = (i == j) ? 0 : INT_MAX;

    Relax through a middle node k

    For each pair (i, j) ask: is going i -> k -> j cheaper than what I have? If yes, overwrite. The outer loop must be k, so that after round k every path may use nodes 0..k as stop-overs.

    for k: for i: for j:
  if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];

    Guard against infinity

    INT_MAX + something overflows and becomes a huge negative number. Always check that both halves are not infinity before adding.

    if (d[i][k] != INT_MAX && d[k][j] != INT_MAX && ...)

    Negative cycle check

    After the three loops, if any d[i][i] is below 0, node i sits on a cycle whose total weight is negative, so shortest paths are not defined.

    Bellman-Ford recap

    Relax every edge V-1 times. One extra pass that still improves something means a negative cycle is reachable from the source.

    Choosing the algorithm

    Dijkstra: one source, no negative edges, O(E log V). Bellman-Ford: one source, negative edges allowed, O(V·E). Floyd-Warshall: every pair, small n (about n <= 500), O(n^3).

    #include <iostream>
#include <queue>
#include <cstring>
#include <vector>

using namespace std;

int main(){
    int n, e;
    cin >> n >> e;
    int adj_mat[n][n];

    for(int i=0; i<n; i++){
        for(int j=0; j<n; j++){
            if(i == j){
                adj_mat[i][j] = 0;
            } else{
                adj_mat[i][j] = INT_MAX;
            }
        }
    }

    while(e--){
        int a, b, c;
        cin >> a >> b >> c;
        adj_mat[a][b] = c;
        // adj_mat[b][a] = c; // for undirected graph
    }

    for(int k=0; k<n; k++){
        for(int i=0; i<n; i++){
            for(int j=0; j<n; j++){
                // adj_mat[i][j] = min(adj_mat[i][j], adj_mat[i][k] + adj_mat[k][j]);
                if(adj_mat[i][k] != INT_MAX && adj_mat[k][j] != INT_MAX && adj_mat[i][k] + adj_mat[k][j] < adj_mat[i][j]){
                    adj_mat[i][j] = adj_mat[i][k] + adj_mat[k][j];
                }
            }
        }
    }

    for(int i=0; i<n; i++){
        for(int j=0; j<n; j++){
            if(adj_mat[i][j] == INT_MAX){
                cout << "INF ";
            } else{
                cout << adj_mat[i][j] << " ";
            }
        }
        cout << endl;
    }

    return 0;
}

    0 3 4 6

    Reading the output. Row i, column j is the cheapest cost from i to j. Row 0 is 0 3 4 6: the direct edge 0->2 costs 7, but 0->1->2 costs 3+1 = 4, so the table keeps 4. Row 1 starts with 9 because 1->2->3->0 = 1+2+6.

    How it works, step by step
    1. Read n nodes and e edges; build adj_mat[n][n] with 0 on the diagonal and INT_MAX elsewhere.
    2. For each edge a b c store adj_mat[a][b] = c (only one direction, the graph is directed).
    3. Outer loop k picks the stop-over node; inner loops i, j try every pair.
    4. If both adj_mat[i][k] and adj_mat[k][j] are finite and their sum is smaller, update adj_mat[i][j].
    5. Print the matrix row by row, writing INF for INT_MAX.
    Watch out. INT_MAX comes from <climits>; the file does not include it and only compiles because this compiler pulls it in through another header. Add #include <climits> to be safe.
    ✅ Check yourself: Why must k be the outermost loop?
    Because after finishing round k, every pair already knows the best path that uses only nodes 0..k in the middle. If k were inside, a pair could be finalised before the stop-over nodes it needs were processed.

https://www.geeksforgeeks.org/problems/distance-from-the-source-bellman-ford-algorithm/1

Bellman-Ford

Given a weighted and directed graph of v vertices and edges, Find the shortest distance of all the vertex's from the source 
vertex, src and return a list of integers where the ith integer denotes the distance of the ith node from the source node. If a 
vertices can't be reach from the s then mark the distance as 10^8.
Note: If there exist a path to a negative weighted cycle from the source node then return {-1}.

Examples:

Input: edges = [[0,1,9]], src = 0

Output: [0, 9]
Explanation: Shortest distance of all nodes from source is printed

Input: edges = [[0,1,5], [1,0,3], [1,2,-1], [2,0,1]], src = 2
Output: [1, 6, 0]
Explanation: For nodes 2 to 0, we can follow the path: 2-0. This has a distance of 1. For nodes 2 to 1, we cam follow the path: 
2-0-1, which has a distance of 1+5 = 6,

Constraints:
1 ≤ V ≤ 500
1 ≤ E ≤ V*(V-1)
-1000 ≤ data of nodes, weight ≤ 1000
0 ≤ S < V

*/

#include <iostream>
#include <queue>
#include <cstring>
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
    public:
      /*  Function to implement Bellman Ford
       *   edges: vector of vectors which represents the graph
       *   src: source vertex
       *   V: number of vertices
       */
      vector<int> bellmanFord(int V, vector<vector<int>>& edges, int src) {
          // Code here
          vector<int> dist(V, 100000000);
          dist[src] = 0;
          
          for(int i=0; i< V-1; i++){
              for(auto edge : edges){
                  int u = edge[0];
                  int v = edge[1];
                  int w = edge[2];
                  if(dist[u] != 100000000 && dist[u] + w < dist[v]){
                      dist[v] = dist[u] + w;
                  }
              }
          }
          
          for(auto edge : edges){
              int u = edge[0];
              int v = edge[1];
              int w = edge[2];
              if(dist[u] != 100000000 && dist[u] + w < dist[v]){
                  return {-1};
              }
          }
          return dist;
      }
  };

    V E, then E edges u v w, then the source. This is the judge's second example.

    Output 
    dist = 1 6 0

    Reading the output. Prints dist = 1 6 0, matching the judge's expected [1, 6, 0]: from 2 the edge to 0 costs 1, and 2->0->1 costs 1+5 = 6. If a negative cycle were reachable you would see dist = -1.

    How it works, step by step
    1. Create dist(V, 100000000) (the judge's 'infinity') and set dist[src] = 0.
    2. Repeat V-1 times: for every edge u v w, if dist[u] is finite and dist[u] + w < dist[v], update dist[v].
    3. Why V-1? A shortest path without cycles has at most V-1 edges, and each pass fixes at least one more edge of it.
    4. Do one more pass over all edges. If anything still improves, return {-1}.
    5. Otherwise return dist.
    Watch out. The file only holds the judge's Solution class; the page adds a small test driver to run it.
    ✅ Check yourself: Why check dist[u] != 100000000 before relaxing?
    An unreachable u has no real distance. Adding a negative w to the 'infinity' value would wrongly make v look reachable.

    /*

https://www.geeksforgeeks.org/problems/implementing-floyd-warshall2042/1

Floyd Warshall

The problem is to find the shortest distances between every pair of vertices in a given 
edge-weighted directed graph. The graph is represented as an adjacency matrix. mat[i][j] 
denotes the weight of the edge from i to j. If mat[i][j] = -1, it means there is no edge 
from i to j.
Note: Modify the distances for every pair in place.

Examples :
Input: mat = [[0, 25], [-1, 0]]
Output: [[0, 25], [-1, 0]]
Explanation: The shortest distance between every pair is already given(if it exists).

Input: mat = [[0, 1, 43],[1, 0, 6], [-1, -1, 0]]
Output: [[0, 1, 7], [1, 0, 6], [-1, -1, 0]]
Explanation: We can reach 2 from 0 as 0->1->2 and the cost will be 1+6=7 which is less than 
43.

Constraints:
1 <= mat.size() <= 100
-1 <= mat[ i ][ j ] <= 1000

*/

#include <iostream>
#include <queue>
#include <cstring>
#include <vector>

using namespace std;

// User function template for C++
class Solution {
    public:
        void shortestDistance(vector<vector<int>>& mat) {
            int n = mat.size();

            for(int i=0; i<n; i++){
                for(int j=0; j<n; j++){
                    if(mat[i][j] == -1){
                        mat[i][j] = INT_MAX;
                    }
                }
            }

            for(int k=0; k<n; k++){
                for(int i=0; i<n; i++){
                    for(int j=0; j<n; j++){
                        if(mat[i][k] != INT_MAX && mat[k][j] != INT_MAX && 
                        mat[i][k] + mat[k][j] < mat[i][j]){
                            mat[i][j] = mat[i][k] + mat[k][j];
                        }
                    }
                }
            }

            for(int i=0; i<n; i++){
                for(int j=0; j<n; j++){
                    if(mat[i][j] == INT_MAX){
                        mat[i][j] = -1;
                    }
                }
            }
        }    
};


// Driver Code Starts.
int main() {
    int tc;
    cin >> tc;
    while (tc--) {
        int n;
        cin >> n;
        vector<vector<int>> matrix(n, vector<int>(n, -1));
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                cin >> matrix[i][j];
            }
        }

        Solution obj;
        obj.shortestDistance(matrix);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                cout << matrix[i][j] << " ";
            }
            cout << "\n";
        }

        cout << "~\n";
    }
    return 0;
}

    Reading the output. First test: 0 1 43 becomes 0 1 7 because 0->1->2 costs 1+6. Row 2 stays -1 -1 0 since node 2 has no outgoing edges. Each matrix ends with a ~ line.

    How it works, step by step
    1. Replace every -1 with INT_MAX so the comparisons work (otherwise -1 would look like a very cheap edge).
    2. Run the usual k, i, j loops with the infinity guard.
    3. Replace every remaining INT_MAX with -1 to match the judge's format.
    4. The driver main reads tc test cases, calls shortestDistance, and prints each matrix followed by ~.
    Watch out. The 'convert sentinel, compute, convert back' pattern matters: forgetting the first step makes -1 act like a negative edge.
    ✅ Check yourself: What goes wrong if you skip turning -1 into infinity?
    The algorithm treats -1 as an edge of weight -1, so it happily routes through 'missing' edges and produces wrong, too-small distances.

    #include <iostream>
#include <queue>
#include <cstring>
#include <vector>
#include <algorithm>

using namespace std;

int main(){
    int n, e, q;
    cin >> n >> e >> q;
    long long int adj_mat[n][n];

    for(int i=1; i<=n; i++){
        for(int j=1; j<=n; j++){
            if(i == j){
                adj_mat[i][j] = 0;
            } else{
                adj_mat[i][j] = LLONG_MAX;
            }
        }
    }

    while(e--){
        long long int a, b, c;
        cin >> a >> b >> c;
        adj_mat[a][b] = min(adj_mat[a][b], c);
        adj_mat[b][a] = min(adj_mat[a][b], c); // we have undirected graph here
    }

    for(int k=1; k<=n; k++){
        for(int i=1; i<=n; i++){
            for(int j=1; j<=n; j++){
                // adj_mat[i][j] = min(adj_mat[i][j], adj_mat[i][k] + adj_mat[k][j]);
                if(adj_mat[i][k] != LLONG_MAX && adj_mat[k][j] != LLONG_MAX && adj_mat[i][k] + adj_mat[k][j] < adj_mat[i][j]){
                    adj_mat[i][j] = adj_mat[i][k] + adj_mat[k][j];
                }
            }
        }
    }

    while(q--){
        int s, d;
        cin >> s >> d;
        if(adj_mat[s][d] == LLONG_MAX){
            cout << "-1" << endl;
        } else {
            cout << adj_mat[s][d] << endl;
        }
    }

    return 0;
}

    How it works, step by step
    1. Fill the matrix for nodes 1..n: 0 on the diagonal, LLONG_MAX elsewhere.
    2. For every road keep the cheapest one: adj_mat[a][b] = min(adj_mat[a][b], c) and the same for [b][a].
    3. Run the triple loop once; this is the expensive O(n^3) part.
    4. For each query just look up adj_mat[s][d]; print -1 if it is still LLONG_MAX.
    Watch out. The matrix is declared long long adj_mat[n][n] but the loops use indices 1..n, so index n is outside the array and the program crashes. Fix: declare adj_mat[n+1][n+1] (or a global [505][505]). Also, a 500x500 local long long array is 2 MB; making it global is safer.
    ✅ Check yourself: Why read all roads with min(...) instead of plain assignment?
    There can be several roads between the same two cities. A later, more expensive road must not overwrite a cheaper one that was read earlier.

    📌 Remember

    • Floyd-Warshall = three loops, k outside, relax d[i][j] through k.
    • Initialise with 0 on the diagonal and infinity elsewhere; guard every addition against infinity.
    • A negative value on the diagonal after the loops means a negative cycle.
    • Use it when n is small and you need many pair queries: pay O(n^3) once, answer each query in O(1).
    • Keep the minimum when the input can repeat an edge.

    ✅ Check yourself

    n = 400. Is Floyd-Warshall fast enough?
    400^3 = 64 million simple steps, which is fine within about a second.
    When would you pick Bellman-Ford over Floyd-Warshall?
    When you only need distances from one source (or n is too big for n^3) and edges can be negative.
    Why use long long for distances in Shortest Routes II?
    A path can use up to n-1 roads each costing up to 10^9, so the total can exceed the int limit.
